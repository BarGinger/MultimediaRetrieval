\section{Introduction} \label{sec:introduction}

Content-based 3D shape retrieval addresses the fundamental challenge of identifying similar three-dimensional objects within large databases using geometric and topological properties rather than textual metadata. Given a query shape, such systems must rank database entries by similarity and return the most relevant matches, requiring sophisticated understanding of shape characteristics across different scales and representations.

In this work, we implement a complete 3D shape retrieval system using a collection of triangular meshes spanning diverse semantic categories and geometric complexities. Originating from the Princeton Shape Benchmark \cite{shilane2004princeton}, the dataset includes everyday objects, vehicles, buildings, tools, and animal models, offering a broad test-suite for evaluating retrieval accuracy and computational performance.

The system was developed through six main stages: data visualization and preprocessing, geometric normalization, feature extraction, similarity metric design, spatial indexing, and performance evaluation. Each stage builds on the previous to form an end-to-end pipeline that allows querying a shape and retrieving the most similar objects from the database. The following sections describe these stages in detail and present the results of our evaluation. The full source code to our project is available via \href{https://github.com/BarGinger/MultimediaRetrieval.git}{GitHub}.

\section{Dataset}
For this multimedia retrieval assignment, we utilized a comprehensive 3D shape database containing diverse geometric objects organized into semantic categories. The database comprises shapes sourced from the Princeton Shape Benchmark \cite{shilane2004princeton}, offering a diverse range of 3D mesh objects suitable for content-based shape retrieval research. The complete data set used can be found \href{https://github.com/BarGinger/MultimediaRetrieval/tree/4489fb12a23cc732ef120aa5b21304f50ea49b45/Datasets/Data}{here}.

The dataset comprises 2,483 3D mesh objects distributed across 69 distinct semantic categories, ranging from everyday objects like chairs, tables, and cups to more specialized items such as aircraft, musical instruments, and architectural elements. This diversity ensures comprehensive coverage of different shape characteristics, geometric complexities, and semantic domains essential for robust retrieval system evaluation. The category distribution ranges from 15 to 143 shapes per category, with an average of 36.0 shapes per category and a median of 27 shapes per category.

Each shape in the database is associated with a class label corresponding to its semantic category, derived from the original benchmark collections' folder organization structure. These class labels serve as ground truth for evaluation purposes in our content-based shape retrieval system. The shapes are stored in OBJ format \cite{bourke1999obj}, a widely-used standard for 3D mesh representation, containing vertex coordinates, face connectivity information, and associated geometric metadata.

The collection, as detailed in Table \ref{tab:dataset_composition}, exhibits significant variety in geometric complexity, with shapes averaging 5,908 vertices and 12,110 faces per object. This natural variation in mesh resolution and complexity provides an excellent testbed for evaluating the robustness and effectiveness of different shape descriptors and retrieval algorithms across objects of varying geometric detail and structural characteristics. Given the inherent variability in mesh resolution and geometric representation across the collection, a systematic preprocessing and normalization pipeline was essential to ensure consistent feature extraction and reliable retrieval performance. The comprehensive details of this multi-step process are presented in Sections \ref{step2} and \ref{step3}.

\section{Mathematical Notations}
\label{sec:notation}

\subsection{General conventions.}
\begin{itemize}
    \item Bold lowercase letters (\(\mathbf{x},\mathbf{y},\mathbf{v}\)) denote vectors in \(\mathbb{R}^3\); uppercase Greek (e.g., \(\Sigma\)) denote matrices.
    \item \(\lVert\cdot\rVert_2\): Euclidean norm; \(\cdot\): dot product; \(\times\): cross product.
    \item For a set \(S\), \(|S|\) is its cardinality; for a scalar \(a\), \(|a|\) is absolute value (context disambiguates).
    \item \(\operatorname{sign}(\cdot)\): sign function; \(\odot\): element-wise (Hadamard) product.
\end{itemize}

\subsection{Meshes and topology.}
\begin{itemize}
    \item \(M=(V,F)\): a triangular mesh.
    \item \(V=\{\mathbf{v}_1,\ldots,\mathbf{v}_n\}\subset\mathbb{R}^3\): vertex set; \(n=|V|\).
    \item \(F=\{f_1,\ldots,f_m\}\): face set with \(f_j=(i,j,k)\) an ordered triple of vertex indices; \(m=|F|\).
    \item \(E\): set of unique undirected mesh edges extracted from \(F\).
    \item \(T\): set of triangles (we use \(T\equiv F\) when summing over triangles).
    \item \(\mathbf{n}_f\): unit normal of face \(f\); \(\mathbf{n}_i\): vertex normal at \(\mathbf{v}_i\) (area-weighted average of incident face normals).
    \item \(\tau(f_j)\): polygon type of face \(f_j\) (triangle, etc.); \(\mathcal{T}(M)=\{\tau(f_j)\mid f_j\in F\}\).
    \item \(c \in \mathcal{C}_{\mathrm{cls}}\): semantic class label; \(\mathcal{C}_{\mathrm{cls}}\) is the set of classes.
    \item \(\mathcal{C}_{\mathrm{cmp}}(M)\): set of connected face components of \(M\) (used in the signed-volume sum).
          \emph{Note.} When \(\mathcal{C}(M)\) appears in formulas, it refers to \(\mathcal{C}_{\mathrm{cmp}}(M)\).
\end{itemize}

\subsection{Bounding boxes, centering and scaling.}
\begin{itemize}
    \item \(B(M)=[\mathbf{v}_{\min},\mathbf{v}_{\max}]\): axis-aligned bounding box (AABB), with
          \(\mathbf{v}_{\min}=(\min_i v_i^x,\min_i v_i^y,\min_i v_i^z)\),
          \(\mathbf{v}_{\max}=(\max_i v_i^x,\max_i v_i^y,\max_i v_i^z)\).
    \item \(\mathbf{s}=(s_x,s_y,s_z)=\mathbf{v}_{\max}-\mathbf{v}_{\min}\); \(s_{\max}=\max(s_x,s_y,s_z)\); uniform scale \(\alpha=1/s_{\max}\).
    \item \(\mathbf{b}(M)\): mass barycenter (area-weighted triangle centroid average).
          For triangle \(t=(a,b,c)\), \(A(t)=\tfrac{1}{2}\lVert(\mathbf{v}_b-\mathbf{v}_a)\times(\mathbf{v}_c-\mathbf{v}_a)\rVert\),
          \(c(t)=\tfrac{1}{3}(\mathbf{v}_a+\mathbf{v}_b+\mathbf{v}_c)\), and
          \(\mathbf{b}(M)=\big(\sum_{t\in T} A(t)c(t)\big)\big/\big(\sum_{t\in T} A(t)\big)\).
    \item Tolerances: \(\epsilon_{\text{area}}>0\) (degenerate-area guard), \(\epsilon_{\text{recenter}}>0\) (recentering threshold).
\end{itemize}

\subsection{Normalization transforms and PCA.}
\begin{itemize}
    \item \(v_i^{(0)}=\mathbf{v}_i\) (original). After step \(k\in\{1,2,3,4\}\): \(v_i^{(k)}=(T_k\circ\cdots\circ T_1)(\mathbf{v}_i)\):
          \begin{enumerate}[label=(\arabic*)]
              \item \(T_1\) (translation): center at \(\mathbf{b}(M)\).
              \item \(T_2\) (alignment): PCA alignment to principal axes.
              \item \(T_3\) (flipping): axis-sign disambiguation via signed moments.
              \item \(T_4\) (scaling): fit to unit cube (\(\max\) side length \(=1\)).
          \end{enumerate}
    \item PCA on centered vertices: covariance \(\Sigma\), eigenpairs \((\lambda_i,\mathbf{u}_i)\), sorted \(\lambda_1\ge\lambda_2\ge\lambda_3\ge 0\).
    \item Right-handed orthonormal basis: \(\mathbf{e}_1=\mathbf{u}_1/\|\mathbf{u}_1\|,\ \mathbf{e}_2=\mathbf{u}_2/\|\mathbf{u}_2\|\),
          \(\mathbf{e}_3=\mathbf{e}_1\times\mathbf{e}_2\).
          Aligned coordinates: \(v_j^{(2)}=[\mathbf{e}_1^\top v_j^{(1)},\ \mathbf{e}_2^\top v_j^{(1)},\ \mathbf{e}_3^\top v_j^{(1)}]^\top\).
    \item Flipping moments: for triangle centroid \(\mathbf{C}_t\), \(f_i=\sum_{t\in T}\operatorname{sign}(C_{t,i})\, C_{t,i}^2\) (\(i=0,1,2\)).
          Apply \(v^{(3)}=v^{(2)}\odot[\operatorname{sign}(f_0),\operatorname{sign}(f_1),\operatorname{sign}(f_2)]^\top\).
    \item Axis extents after flipping: \(d_i=\max_j v^{(3)}_{j,i}-\min_j v^{(3)}_{j,i}\), \(d_{\max}=\max(d_0,d_1,d_2)\),
          scale \(v^{(4)}=v^{(3)}/d_{\max}\).
\end{itemize}

\subsection{Geometric functionals.}
\begin{itemize}
    \item \(\mathrm{Area}(M)=A(M)=\tfrac12\sum_{(i,j,k)\in F}\lVert(\mathbf{v}_j-\mathbf{v}_i)\times(\mathbf{v}_k-\mathbf{v}_i)\rVert\).
    \item \(\mathrm{Vol}(M)\) (a.k.a.\ \(V(M)\) in formulas): per-component signed volume summed in absolute value,
          \(\mathrm{Vol}(M)=\sum_{c\in\mathcal{C}_{\mathrm{cmp}}(M)}\left|\tfrac{1}{6}\sum_{(i,j,k)\in F_c}\mathbf{v}_i\cdot\big((\mathbf{v}_j-\mathbf{v}_i)\times(\mathbf{v}_k-\mathbf{v}_i)\big)\right|\).
    \item \(M^{\mathrm{hull}}\): convex hull of \(M\).
    \item Oriented bounding box (OBB): side lengths \((w,h,d)\) with \(V_{\mathrm{OBB}}(M)=w\,h\,d\).
    \item \(D(M)=\max_{\mathbf{p},\mathbf{q}\in V}\lVert\mathbf{p}-\mathbf{q}\rVert_2\): (graph-independent) geometric diameter.
\end{itemize}

\subsection{Scalar shape descriptors.}
\begin{itemize}
    \item \textbf{Surface-to-Volume Ratio}:
          \(\displaystyle \mathrm{SVR}(M)=\frac{A(M)}{\mathrm{Vol}(M)}.\)
    \item \textbf{Sphericity}:
          \(\displaystyle \Psi(M)=\frac{\pi^{1/3}\!\left(6\,\mathrm{Vol}(M)\right)^{2/3}}{A(M)}.\)
    \item \textbf{Compactness}:
          \(\displaystyle \mathrm{Comp}(M)=\frac{A(M)^3}{36\pi\,\mathrm{Vol}(M)^2}.\)
    \item \textbf{Rectangularity}: \(\mathcal{R}(M)=\frac{\mathrm{Vol}(M)}{V_{\mathrm{OBB}}(M)}\in(0,1].\)
    \item \textbf{Convexity}: \(\mathcal{CX}(M)=\frac{\mathrm{Vol}(M)}{\mathrm{Vol}(M^{\mathrm{hull}})}\in(0,1].\)
    \item \textbf{Eccentricity}: with PCA eigenvalues \(\lambda_1\ge\lambda_2\ge\lambda_3\),
          \(\varepsilon(M)=\lambda_1/\lambda_3.\)
\end{itemize}

\subsection{Distribution-based descriptors and sampling.}
\begin{itemize}
    \item Default sampling: \(S=100{,}000\) i.i.d.\ samples; histogram bins \(H=20\); histograms are \emph{L1-normalized}.
    \item \textbf{A3} (angle): for \((\mathbf{x},\mathbf{y},\mathbf{z})\in V^3\),
          \(\theta=\arccos\!\frac{(\mathbf{y}-\mathbf{x})\cdot(\mathbf{z}-\mathbf{x})}{\lVert\mathbf{y}-\mathbf{x}\rVert\,\lVert\mathbf{z}-\mathbf{x}\rVert}\).
          Histogram limits use the empirical \(99^\text{th}\) percentile plus \(10\%\) margin.
    \item \textbf{D1} (barycenter distance): \(d_1=\lVert \mathbf{x}-\mathbf{b}(M)\rVert_2\) for \(\mathbf{x}\in V\).
    \item \textbf{D2} (pairwise distance): \(d_2=\lVert \mathbf{x}-\mathbf{y}\rVert_2\) for \((\mathbf{x},\mathbf{y})\in V^2\).
    \item \textbf{D3} (triangle area, square-rooted): for \((\mathbf{x},\mathbf{y},\mathbf{z})\in V^3\),
          \(A_\triangle=\tfrac12\lVert(\mathbf{y}-\mathbf{x})\times(\mathbf{z}-\mathbf{x})\rVert\); histogram uses \(\sqrt{A_\triangle}\).
    \item \textbf{D4} (tetrahedron volume, cube-rooted): for \((\mathbf{w},\mathbf{x},\mathbf{y},\mathbf{z})\in V^4\),
          \(V_{\mathrm{tet}}=\tfrac16\big|(\mathbf{x}-\mathbf{w})\cdot\big((\mathbf{y}-\mathbf{w})\times(\mathbf{z}-\mathbf{w})\big)\big|\);
          histogram uses \(\sqrt[3]{V_{\mathrm{tet}}}\).
    \item \(P_{99}[\cdot]\): empirical \(99^\text{th}\) percentile used to set descriptor-specific histogram maxima (then expanded by \(10\%\)).
\end{itemize}

\subsection{Distance combination and normalization.}
\begin{itemize}
    \item \(D_i(M_a, M_b)\): raw distance between meshes \(M_a\) and \(M_b\) for descriptor \(i\).
    \item \(R_i(M_a, M_b)\): rank-normalized distance for descriptor \(i\).
    \item \(w_i\): weight assigned to descriptor \(i\) in the combined distance metric.
    \item \(D_{\text{combined}}(M_a, M_b)\): final weighted distance between two meshes.
    \item \(W_1(p,q)\): Earth Mover’s (Wasserstein-1) distance between distributions \(p\) and \(q\).
\end{itemize}

\subsection{Disambiguation (to match symbols used elsewhere in the text).}
\begin{itemize}
    \item \(V\) denotes the \emph{vertex set}. When you see \(V(M)\) in equations for volume, read it as \(\mathrm{Vol}(M)\).
    \item \(\mathcal{C}\) is overloaded in the manuscript: \(\mathcal{C}_{\mathrm{cls}}\) (class set), 
          \(\mathcal{C}_{\mathrm{cmp}}(M)\) (connected components), and \(\mathrm{Comp}(M)\) (compactness; written as \(\mathcal{C}(M)\) in Sec.~\ref{step3}). 
          The above table makes each meaning explicit to avoid ambiguity.
\end{itemize}

\subsection{Framework Architecture and Design Rationale}

The viewer app was developed as a web-based application, using Dash \cite{dash} to manage reactive interactions and Plotly \cite{plotly} to provide efficient 3D visualization capabilities. The selection of this technology stack was guided by three requirements: 
\begin{enumerate}
    \item Real-time interactive exploration of the large mesh dataset.
    \item Cross-platform accessibility without the need for specialized 3D software.
    \item Seamless integration with Python-based scientific computing tools for efficient data processing, such as Pandas~\cite{mckinney2011pandas} and NumPy \cite{harris2020array}.

\section{Step 1: Read and view the data}

Effective retrieval requires a clear understanding of the dataset at hand. To address this, our system begins with the development of an exploration and visualization framework tailored to 3D meshes. The following subsections provide a detailed breakdown of the application's implementation.

The purpose of this stage is to establish a comprehensive environment for systematic analysis of the mesh datasets. Interactive visualization is a central component in multimedia retrieval, as it enables researchers to assess data distributions, identify potential preprocessing challenges, and validate algorithmic decisions.

\subsection{Data Format Processing and Geometric Representation}

Our system processes triangular mesh data stored in the Wavefront OBJ format, which has become the de facto standard for 3D model interchange due to its simplicity and widespread software support \cite{bourke1999obj}. The OBJ format represents 3D objects through two primary components: vertex coordinates defining spatial geometry and face definitions specifying triangular connectivity.

We implemented a custom \texttt{OBJParser} class that addresses several technical challenges inherent in OBJ processing:

\begin{itemize}
    \item \textbf{Index Convention Translation}: OBJ files use 1-based indexing while NumPy arrays require 0-based
    \item \textbf{Polygon Triangulation}: Automatic conversion of quad faces to triangles through diagonal splitting, ensuring consistent triangular mesh representation required for downstream processing
    \item \textbf{Robust Parsing}: Error handling for malformed geometry definitions and missing vertex references
\end{itemize}

The parser extracts vertex coordinates $V = \{v_1, v_2, \ldots, v_n\}$ where $v_i \in \mathbb{R}^3$ and face connectivity $F = \{f_1, f_2, \ldots, f_m\}$ where each face $f_j$ contains three vertex indices, forming the fundamental mesh representation $M = (V, F)$ used throughout our retrieval pipeline.

\subsection{Interactive Visualization System}

The visualization component leverages Plotly's WebGL-based 3D rendering engine, which provides hardware-accelerated graphics suitable for real-time interaction with complex meshes \cite{qin2021web}. Our implementation incorporates several advanced rendering techniques:

To visualize 3D shapes in our web application, we use the textit{Mesh3d} object from the Plotly Graph Objects library \cite{go}. This tool allows us to render interactive 3D meshes directly in the browser, providing smooth rotation, zooming, and lighting effects. By leveraging Plotly's capabilities, we can display complex surfaces and wireframes in a user-friendly way.

\subsubsection{Wireframe Edge Visualization}

Our optional wireframe overlay uses an efficient edge extraction method that avoids duplicate edges by storing them in a set. For each face $f$ in the set of faces $F$, we iterate over its edges. Each edge is represented by a pair of vertex indices, sorted to ensure consistency. We add each sorted edge to the set $E$, which automatically removes duplicates.

This set-based approach guarantees $O(F)$ complexity for edge extraction, where $F$ is the number of faces. The resulting set contains $E$ unique edges. This significantly reduces rendering overhead compared to naive enumeration of all face edges~\cite[pp.~17-19]{botsch2010polygon}.

\begin{algorithm}[H]
\SetAlgoLined
\KwIn{Set of faces $F$ (each face is a list of vertex indices)}
\KwOut{Set of unique edges $E$}
$E \gets \emptyset$\tcp*[l]{Initialize empty edge set}
\ForEach{face $f \in F$}{
    \For{$i \gets 0$ \KwTo $|f|-1$}{
        $v_1 \gets f[i]$\;
        $v_2 \gets f[(i+1) \bmod |f|]$\;
        $edge \gets \text{sort}(v_1, v_2)$\tcp*[l]{Sort vertex indices for consistency}
        $E \gets E \cup \{edge\}$\tcp*[l]{Add edge to set (deduplication)}
    }
}
\Return{$E$}
\caption{Efficient Wireframe Edge Extraction}
\end{algorithm}

\subsection{Hierarchical Data Organization and Metadata Extraction}

To facilitate systematic exploration and evaluation, we utilized the organization of the 3D models into a hierarchical directory structure by category. \section{Step 2: Preprocessing and cleaning} \label{step2}
The dataset contains a large variety of 3D objects that differ significantly in complexity, resolution and overall quality. Before features can be reliably extracted and used for retrieval, it is essential to ensure that all shapes satisfy certain quality requirements. Poorly sampled meshes, inconsistent scaling, or misaligned objects may bias the descriptors extracted later on, which in turn reduces the effectiveness and fairness of the retrieval system.

In this section, we analyze the structural characteristics of all shapes in the database and identify common irregularities such as extreme outliers in the number of vertices and faces, as well as variations in scale and positioning. By collecting global statistics over the dataset, we obtain a better understanding of its variability and can determine which objects require resampling or refinement.

Next, we apply a set of preprocessing operations to improve dataset consistency. These operations include mesh simplification for overly large shapes, refinement for undersampled ones, and normalization to standardize the position and scale of each object. The resulting database forms a more balanced and homogeneous foundation for the subsequent feature extraction stage, ensuring that differences in descriptors reflect meaningful shape characteristics rather than artifacts of the raw input data.

\subsection{Step 2.1: Analyzing a single shape}
Before starting the preprocessing and cleaning of the dataset, we first obtain an overview of the initial variability of the objects. 
For this purpose, we implemented a simple analysis tool that reports, for each shape $M = (V, F)$, the following properties:
\begin{itemize}
    \item The semantic class label $c \in \mathcal{C}$ of the shape.
    \item The number of vertices $|V|$ and the number of faces $|F|$.
    \item The set of face types $\mathcal{T}(M)$, which indicates whether the shape consists of only triangles, only quadrilaterals, or a mixture of polygon types.
    \item The axis-aligned bounding box $B(M) = [\mathbf{v}_{\min}, \mathbf{v}_{\max}]$, defined by the minimum and maximum coordinates among all vertices.
\end{itemize}
This information provides a concise summary of the raw dataset characteristics and highlights potential sources of variability that may need to be addressed in subsequent preprocessing steps.

The tool operates by iterating over all files in the dataset in \texttt{.obj} format. In this format, each line encodes either a vertex position (\texttt{v}), a vertex normal (\texttt{vn}), or a face (\texttt{f}). During parsing, each vertex is added to the set $V$, and each face to the set $F$, while ignoring additional attributes such as normals and texture coordinates. Once all lines have been processed, we directly obtain $|V|$ and $|F|$. The bounding box $B(M)$ is computed by taking the coordinate-wise minima and maxima of the vertices. Face types are determined by checking the number of vertices in each face, distinguishing between triangles, quadrilaterals, and higher-order polygons. 

The extracted statistics are written to a comma-separated values (\texttt{CSV}) file, producing one record per shape. In the next step, we will aggregate these records to obtain statistics over the entire dataset.

\subsection{Step 2.3. Resampling outliers} \label{step2.3}
%Why remesh?%
From the obtained statistics it has become clear that the dataset contains a wide variety of shapes. To ensure fair and unbiased feature extraction and object retrieval, it is necessary to reduce the influence of extreme outliers in terms of vertex count. For this reason, we apply a remeshing step that regularizes the mesh resolution across the dataset. This ensures that all shapes are represented at a comparable level of detail, making subsequent analysis and retrieval more consistent and reliable.

%Target vertex count, why this?%
For the remeshing step, it is necessary to specify a target resolution in terms of vertex count. We chose a nominal target of $7{,}500$ vertices, which offers a good compromise between preserving geometric detail and maintaining manageable processing times. Because it is often impractical to achieve exactly this number of vertices, we allow a tolerance range of $5{,}000$ to $10{,}000$ vertices. Remeshing therefore stops once the mesh falls within this range, ensuring both consistency across the dataset and robustness of the preprocessing pipeline.

%What tools were used?%
The remeshing procedure was implemented using \textbf{Open3D} \cite{Zhou2018} (version $\geq$0.18), an open-source library for 3D data processing. Open3D provides efficient tools for handling triangle meshes, including vertex and triangle access, mesh cleaning, simplification, and subdivision. Its functions for \emph{quadric-based decimation} and \emph{midpoint subdivision} were used to adjust mesh resolution while preserving the shape of the geometry. Additionally, \textbf{NumPy} \cite{harris2020array} was employed for numerical computations, nearest-neighbor searches, and vertex reprojection.

The goal of the remeshing step is to reduce the variation in mesh resolution across the dataset and limit the influence of outlier meshes. The algorithm works as follows:

\begin{enumerate}
    \item \textbf{Vertex Count Check:} Each mesh is first checked against the target vertex range of 5,000 to 10,000 vertices (nominal target: 7,500). Meshes that are already within this range are copied without modification.

    \item \textbf{Upsampling:} Meshes with fewer vertices than the minimum threshold are increased in resolution using a \emph{feature-preserving midpoint subdivision}. New vertices are projected toward local planes or neighborhood centroids to maintain surface features and prevent excessive smoothing. This process is repeated in multiple passes until the mesh reaches the desired resolution.

    \item \textbf{Downsampling:} Meshes exceeding the maximum vertex threshold are simplified using \emph{quadric-based decimation}. The reduction is applied iteratively in multiple passes, with the reduction ratio adapted depending on how far the mesh is from the target. If the decimation stalls, a more aggressive pass is applied to ensure the mesh falls within the target range.

    \item \textbf{Feature Preservation:} Sharp edges and important geometric features are identified based on dihedral angles between adjacent faces. During subdivision and decimation, these features guide the placement of new vertices and the removal of faces to retain the overall shape. Planar regions are preserved by blending vertex positions toward fitted local planes when possible.

    \item \textbf{Fallback and Robustness:} In rare cases where standard upsampling fails, a single subdivision pass followed by light decimation is used. Mesh cleaning operations, such as removal of degenerate triangles and duplicated vertices, are applied throughout to maintain mesh quality.
\end{enumerate}

This approach ensures that all meshes in the dataset have a comparable number of vertices while keeping their geometric features intact, which facilitates consistent feature extraction and object retrieval.

Although the resampling pipeline substantially improved uniformity in vertex counts, a small number of meshes still fall outside of the target range of 5,000-10,000 vertices. This outcome can be explained by the nature of the subdivision and simplification algorithms used. Subdivision increases the number of vertices in large multiplicative steps (approximately by a factor of four for each pass). As a result, meshes that start well below the lower bound often overshoot into the higher range. Simplification is then applied to reduce these meshes, but the algorithm is constrained by geometry preservation: it avoids collapsing important edges or thin structures, and therefore does not always converge exactly within the target window. Similarly, meshes that were already close to the lower bound are sometimes left unchanged, as subdivision would push them unnecessarily far above the acceptable range.

Further attempts to enforce exact compliance would require mesh-specific adjustments, which would be computationally expensive and risk degrading geometric fidelity. The current procedure achieves compliance for approximately 97\% of the dataset, which we consider sufficient for our purposes. The small number of outliers (63) does not meaningfully affect downstream tasks, and avoiding excessive processing helps maintain higher shape quality overall. We will further explore the outliers mentioned above in Sub-Section \ref{removing-outliers}.

It should also be noted that resampling occasionally introduces some surface artifacts. For instance, some meshes show a rippling effect along curved surfaces, such as the body of a bottle, or slight deformations in thin structures, such as the wings of an airplane no longer being perfectly straight (see Figures \ref{Remeshing-Artifacts1} and \ref{Remeshing-Artifacts2}). These cases illustrate the trade-off between vertex count normalization and preservation of fine-grained geometry. While not ideal, such artifacts are limited in scope and do not compromise the overall usability of the dataset.

\subsection{Removing outliers} \label{removing-outliers}

To further check our meshing approach, we zoomed in on a few cases from the 63 shapes that were outside the compiled vertices range. Upon closer inspection, we found that most outliers shared a common characteristic: they were poorly sampled in their original form. The meshing process - which for these low-vertex-count cases involved cleaning followed by upscaling - created holes and detached parts in these problematic cases. For instance, in the jet example (Figure \ref{Remeshing-outlier-jet}), the meshing process both introduced structural defects and overshot the target vertex range (5,000-10,000), reaching 15,794 vertices. In contrast, the bird example (Figure \ref{Remeshing-outlier-bird}) demonstrates a case where the approach implemented an early stop at 1,693 vertices to prevent further distortion of the shape. Interestingly, both the jet and the bird exhibit the most severe problems in their wing structures, which were poorly sampled to begin with. Closer debugging revealed that the cleaning step caused the detachment of these wing parts from the main body, leading to the observed artifacts. Similarly, while the humanoid example (Figure \ref{Remeshing-outlier-humaniod}) only moderately overshot the target range (11,304 vertices), it illustrates how the meshing process introduced numerous holes throughout the body structure.

Based on these observations, we established a systematic criterion for handling outliers. As shown in Table~\ref{table:files_outside_range}, we applied a 15\% tolerance threshold around the target vertex range (5,000-10,000). Shapes whose resampled vertex counts fell within this tolerance - between 4,250 and 11,500 vertices - were retained in the dataset, as minor deviations likely reflected the inherent variability of the meshing process rather than fundamental structural problems. This allowed us to keep 18 shapes that were close to the target range. Notably, of the three examples discussed above, only the humanoid (Figure \ref{Remeshing-outlier-humaniod}) met this criterion with 11,304 vertices, falling just above the target range. While it exhibited structural holes, we retained it with the expectation that subsequent hole-filling step in our pipeline would address these defects. In contrast, the jet and bird examples were excluded, as they exceeded the tolerance threshold. More broadly, the 45 excluded shapes typically exhibited the same underlying issues we identified in our detailed inspection: poor original sampling that led to holes, detached components, or excessive distortion during remeshing. Ultimately, this process yielded a cleaner, more reliable dataset of 2,438 shapes for subsequent analysis.

\subsection{Step 2.5: Normalizing shapes} \label{step2.5}
%Explain why further normalization is needed%
Having reduced the variance in mesh resolution, we next address other characteristics of the dataset that require normalization. In this substep, we translate each object so that its barycenter is positioned at the origin $(0,0,0)$, and uniformly scale it to fit within a unit cube.

Before performing normalization, we first clean each mesh to remove potential geometric inconsistencies that could interfere with the process. This cleaning step ensures that all meshes are topologically valid and free of redundant or ill-defined elements. Specifically, we remove degenerate triangles, duplicated vertices and faces, non-manifold edges, and unreferenced vertices. By doing so, we prevent numerical instabilities during translation and scaling, and ensure that the subsequent computation of the barycenter and bounding box reflects the true geometry of the object.

Once the meshes have been cleaned, we proceed to compute their mass barycenter, which represents the center of mass under the assumption of uniform surface density. In practice, this means that each face contributes to the barycenter in proportion to its area. Rather than simply averaging all vertex coordinates, we therefore compute an area-weighted average of the centroids of all triangular faces, providing a more accurate and robust estimate of the object’s geometric center.



For a triangular mesh $M = (V, F)$ with vertices $V = \{v_1, \dots, v_n\}$, $v_i \in \mathbb{R}^3$, and faces 
$F = \{f_1, \dots, f_m\}$, each face $f_j = (v_{j1}, v_{j2}, v_{j3})$ contributes as follows:

\begin{equation}
c(f_j) = \frac{1}{3}\big(v_{j1} + v_{j2} + v_{j3}\big)
\end{equation}

\begin{equation}
A(f_j) = \frac{1}{2}\,\big\lVert (v_{j2} - v_{j1}) \times (v_{j3} - v_{j1}) \big\rVert
\end{equation}

where $c(f_j)$ is the centroid of face $f_j$ and $A(f_j)$ its area.  
The mass barycenter of the full mesh is then given by

\begin{equation}
b(M) = \frac{\sum_{j=1}^m A(f_j)\,c(f_j)}{\sum_{j=1}^m A(f_j)}
\end{equation}

Before performing this calculation, we remove faces with an area of zero, to ensure a well-defined barycenter for all meshes in the dataset.

We have calculated the offset of the barycenter to the origin of the space before applying the translation normalization. The results can be seen in Figure \ref{Fig-Histogram-Barycenter-Before}. We observe a large variance in this offset over the dataset.

Following the translation, we normalize the scale of each mesh. Formally, we compute the axis-aligned bounding box of a mesh $\mathbf{M}$, defined as

\begin{equation}
B(\mathbf{M}) = [\mathbf{v}_{\min}, \mathbf{v}_{\max}]
\label{eq:bounding_box}
\end{equation}

where

\begin{equation}
\mathbf{v}_{\min} = (\min_i \mathbf{v}_i^x, \min_i \mathbf{v}_i^y, \min_i \mathbf{v}_i^z), \quad
\mathbf{v}_{\max} = (\max_i \mathbf{v}_i^x, \max_i \mathbf{v}_i^y, \max_i \mathbf{v}_i^z)
\end{equation}

We then determine the bounding box side lengths as

\begin{equation}
\mathbf{s} = \mathbf{v}_{\max} - \mathbf{v}_{\min}
\end{equation}

and take the largest dimension

\begin{equation}
s_{\max} = \max(s_x, s_y, s_z)
\end{equation}

To enforce uniform scaling, each vertex is scaled by the factor

\begin{equation}
\alpha = \frac{1}{s_{\max}}
\end{equation}

such that the longest side of the bounding box is mapped to length $1.0$. This guarantees that every object is contained within a unit cube $[-0.5, 0.5]^3$.

\section{Step 3: Feature extraction} \label{step3}

Feature extraction constitutes a critical component of content-based shape retrieval, transforming raw geometric data into compact, discriminative descriptors that capture essential shape characteristics. The effectiveness of any retrieval system fundamentally depends on the quality and robustness of these extracted features, which must be invariant to irrelevant transformations while remaining sensitive to meaningful geometric differences.

This stage consists of two principal components: normalization and descriptor computation. Before features can be meaningfully extracted and compared, all shapes must undergo a rigorous normalization pipeline to eliminate variations in position, orientation, scale, and mesh resolution. This preprocessing ensures that extracted features reflect intrinsic shape properties rather than arbitrary differences in how the meshes were originally authored or captured.

Following normalization, we compute a comprehensive set of shape descriptors spanning both global properties and distribution-based features. Global properties include surface area, volume, and eccentricity, which characterize the overall shape structure. Distribution-based features capture geometric relationships through statistical sampling: the angle between three random points, the distance from barycenter to a random point, the area of triangles formed by three random points, the volume of tetrahedra formed by four random points, and the distance between two random points. These descriptors are designed to capture complementary aspects of shape geometry, providing a rich feature space for subsequent similarity matching.

The implementation of this stage required careful attention to numerical stability, computational efficiency, and compliance with established best practices. We leverage an enhanced mesh class for normalization operations and a dedicated feature extraction class for descriptor computation, with comprehensive validation at each step to ensure correctness.

\subsection{Step 3.1: Full normalization} \label{normalization}

Normalization serves to eliminate extrinsic variations among shapes, ensuring that subsequent feature extraction focuses on intrinsic geometric properties. Our implementation follows a comprehensive five-step normalization pipeline executed in a specific order to maintain mathematical correctness: remeshing, translation, alignment (pose), flipping (orientation), and scaling.

\subsubsection{Pipeline Overview}

The normalization process builds upon the remeshing procedure described in Section \ref{step2}, which standardizes mesh resolution across the dataset to a target range of 5,000 to 10,000 vertices. This remeshing step forms the foundation of our preprocessing pipeline, ensuring that all shapes have comparable geometric complexity before applying geometric transformations. The complete pipeline processes the shapes through the following sequence:

\begin{enumerate}
    \item \textbf{Remeshing}: Standardize mesh resolution (as detailed in \ref{step2.3}, \nameref{step2.3})
    \item \textbf{Translation}: Center the shape at the coordinate origin
    \item \textbf{Alignment}: Rotate to align principal axes with coordinate axes
    \item \textbf{Flipping}: Ensure consistent orientation across similar shapes
    \item \textbf{Scaling}: Fit within a unit bounding box
\end{enumerate}

Each transformation is applied sequentially, with the output of one step serving as input to the next. This order is critical for mathematical correctness. Centering must precede alignment because PCA requires centered data to compute meaningful principal axes. Alignment must precede flipping to establish a consistent reference frame before determining orientation. Scaling must occur last to preserve the geometric relationships established by the previous transformations.

\subsubsection{Mathematical Framework}

Let $M = (V, F)$ represent a triangular mesh with vertices $V = \{v_1, \ldots, v_n\}$ where $v_i \in \mathbb{R}^3$ and faces $F$. After remeshing, the normalization pipeline applies a sequence of transformations:

\begin{equation}
V' = (T_4 \circ T_3 \circ T_2 \circ T_1)(V)
\end{equation}

where $T_1, T_2, T_3, T_4$ represent translation, alignment, flipping, and scaling transformations, respectively, and the composition $(T_4 \circ T_3 \circ T_2 \circ T_1)(V) = T_4(T_3(T_2(T_1(V))))$ indicates that transformations are applied sequentially from right to left.

\textbf{Step 1: Remeshing.} As described in Subsection \ref{step2.3}, \nameref{step2.3}, each mesh is first evaluated against a target vertex range of 5,000 to 10,000 vertices. Meshes already within this acceptable range are identified and move on to the next step without modification, avoiding unnecessary processing that could introduce artifacts or degrade geometric quality. Only meshes falling outside this range undergo adaptive subdivision or decimation to reach the target resolution. This conditional processing ensures that all shapes are represented at comparable levels of detail while preserving the quality of already well-sampled meshes. The approach prevents high-resolution meshes from dominating feature computations and ensures low-resolution meshes have sufficient geometric information, without unnecessarily reprocessing shapes that already meet the quality criteria.

\textbf{Step 2: Translation (Centering).} The remeshed shape is centered at the coordinate frame origin using the mass barycenter $\mathbf{b}(M)$, computed as an area-weighted average of triangle centroids as defined in \ref{step2.5}, \nameref{step2.5}:

\begin{equation}
\mathbf{b}(M) = \frac{\sum_{t \in T} A_t \cdot \mathbf{c}_t}{\sum_{t \in T} A_t}
\end{equation}

where $T$ denotes the set of triangular faces, $A_t$ is the area of triangle $t$, and $\mathbf{c}_t$ is its centroid. For degenerate cases where $\sum_{t \in T} A_t < \epsilon_{\text{area}}$ (we use $\epsilon_{\text{area}} = 10^{-12}$), we fall back to the simple vertex mean. The translation transformation is:

\begin{equation}
v_i^{(1)} = v_i - \mathbf{b}(M)
\end{equation}

To ensure numerical precision, we apply a two-pass recentering approach. After the initial translation, we recompute the residual barycenter $\mathbf{b}_{\text{res}} = \mathbf{b}(V^{(1)})$. If $\|\mathbf{b}_{\text{res}}\| > \epsilon_{\text{recenter}}$ (with $\epsilon_{\text{recenter}} = 10^{-9}$), we apply a correction:

\begin{equation}
v_i^{(1)} \leftarrow v_i^{(1)} - \mathbf{b}_{\text{res}}
\end{equation}

This two-pass approach addresses numerical drift and degeneracy effects that can occur with large meshes or poorly conditioned geometry, ensuring that the mesh is precisely centered even in challenging cases.

\textbf{Step 3: Alignment (Pose Normalization).}  We align the shape's principal axes with the coordinate frame using Principal Component Analysis (PCA) \cite{mackiewicz1993principal} on the centered vertices. We employ the PCA implementation from Scikit-learn \cite{pedregosa2011scikit}, which efficiently computes the covariance matrix of the vertex positions and performs eigenvalue decomposition to obtain three orthogonal eigenvectors.

Let $V = \{v_1, \dots, v_n\} \subset \mathbb{R}^3$ be the vertex positions after centering (Step~2). We compute the sample covariance matrix of the centered vertices
\begin{equation}
\Sigma = \frac{1}{n}\sum_{j=1}^n (v_j - \bar{v})(v_j - \bar{v})^\top,
\end{equation}
where $\bar{v}$ is the arithmetic mean of the centered vertices (after the area-weighted centering correction in Step~2). We then obtain the spectral decomposition (eigendecomposition) of $\Sigma$
\begin{equation}
\Sigma \mathbf{u}_i = \lambda_i \mathbf{u}_i, \qquad i \in \{1, 2, 3\},
\end{equation}
yielding three real eigenvalues $\{\lambda_i\}$ and corresponding orthogonal eigenvectors $\{\mathbf{u}_i\}$.

In our implementation (see \texttt{normalize\_database.py}), we explicitly sort the eigenpairs by descending eigenvalue magnitude so that
\begin{equation}
\lambda_1 \ge \lambda_2 \ge \lambda_3 \ge 0,
\end{equation}
and reorder the associated eigenvectors accordingly. This sorting step guarantees a consistent identification of the major, medium and minor principal axes (major $\leftrightarrow \lambda_1$, medium $\leftrightarrow \lambda_2$, minor $\leftrightarrow \lambda_3$) and is essential for downstream steps that assume this axis ordering (for example, the flipping rule and the subsequent scaling). Sorting also improves robustness when comparing axis directions across shapes.

To enforce a right-handed orthonormal basis we then form
\begin{equation}
\mathbf{e}_1 \leftarrow \frac{\mathbf{u}_1}{|\mathbf{u}_1|}, \qquad \mathbf{e}_2 \leftarrow \frac{\mathbf{u}_2}{|\mathbf{u}_2|},
\end{equation}
and compute the third axis as the cross product
\begin{equation}
\mathbf{e}_3 := \mathbf{e}_1 \times \mathbf{e}_2,
\end{equation}
followed by normalization 
\begin{equation}
\mathbf{e}_3 \leftarrow \frac{\mathbf{e}_3}{|\mathbf{e}_3|}.
\end{equation}
Recomputing $\mathbf{e}_3$ from $\mathbf{e}_1, \mathbf{e}_2$ ensures a numerically consistent right-handed frame even in cases where the raw eigendecomposition introduces small sign or ordering inconsistencies. In degenerate or nearly isotropic cases (very close eigenvalues), the code falls back gracefully: the sorting preserves a deterministic ordering and the cross-product step enforces orthogonality and handedness. Finally, each centered vertex is projected into this principal-axis frame to obtain the aligned coordinates
\begin{equation}
v_j^{(2)} = \begin{bmatrix} \mathbf{e}_1^\top v_j \\ \mathbf{e}_2^\top v_j \\ \mathbf{e}_3^\top v_j \end{bmatrix}, \qquad j = 1, \dots, n,
\end{equation}
i.e., by computing the dot products with the (sorted and normalized) basis vectors. 

\textbf{Step 4: Flipping (Orientation Consistency).} Because eigenvectors are determined only up to sign, the PCA alignment above still leaves a sign ambiguity $\mathbf{e}_i \mapsto \pm\mathbf{e}_i$. To resolve this and obtain a consistent orientation across shapes we apply the moment-based sign test described below. Note that the moment test operates on the axes after we have sorted eigenpairs and enforced a right-handed basis as described in the previous step.

% \textbf{Step 4: Flipping (Orientation Consistency).} Although PCA alignment establishes a canonical pose, it leaves an ambiguity in the sign of each principal axis. Specifically, each eigenvector can be multiplied by $-1$ without affecting the eigenvalue decomposition, meaning that the PCA solution is invariant to axis flipping. To resolve this ambiguity and establish a consistent orientation across all shapes, we apply a moment-based test.

For each coordinate axis $i \in \{0, 1, 2\}$, we compute a signed moment:

\begin{equation}
f_i = \sum_{t \in T} \text{sign}(C_{t,i}) \cdot C_{t,i}^2
\end{equation}

where $C_{t,i}$ is the $i$-th coordinate of triangle $t$'s centroid. This quantity measures the distribution of mass along each axis, with positive values indicating that more mass lies on the positive side and negative values indicating the opposite. We then apply axis-wise flipping to ensure positive moments:

\begin{equation}
v_i^{(3)} = v_i^{(2)} \odot \begin{bmatrix}
\text{sign}(f_0) \\
\text{sign}(f_1) \\
\text{sign}(f_2)
\end{bmatrix}
\end{equation}

where $\odot$ denotes element-wise multiplication. If $f_i = 0$ (indicating perfect symmetry), we set $\text{sign}(f_i) = 1$ to avoid unnecessary flipping. This moment test ensures that similar shapes are oriented consistently, which is essential for rotation-invariant feature extraction.

\textbf{Step 5: Scaling.} The final step scales the shape to fit within a unit bounding box while maintaining aspect ratios. We compute the extent of the aligned and flipped mesh along each axis:

\begin{equation}
d_i = \max_j v_{j,i}^{(3)} - \min_j v_{j,i}^{(3)}, \quad i \in \{0,1,2\}
\end{equation}

and identify the maximum extent:

\begin{equation}
d_{\max} = \max(d_0, d_1, d_2)
\end{equation}

Each vertex is then uniformly scaled by the reciprocal of this maximum extent:

\begin{equation}
v_i^{(4)} = \frac{v_i^{(3)}}{d_{\max}}
\end{equation}

This uniform scaling ensures that the longest dimension of the bounding box equals 1.0 while preserving the shape's aspect ratios. All normalized shapes thus fit within a unit cube centered at the origin.

Following the scaling step, we apply a final safety check by recomputing the barycenter $\mathbf{b}_{\text{final}} = \mathbf{b}(V^{(4)})$. If $\|\mathbf{b}_{\text{final}}\| > \epsilon_{\text{recenter}}$, we apply a final centering correction:

\begin{equation}
v_i^{(4)} \leftarrow v_i^{(4)} - \mathbf{b}_{\text{final}}
\end{equation}

This post-scaling recenter pass ensures that the normalized mesh remains precisely centered at the origin, which is critical for rotation-invariant feature extraction and fair similarity comparisons.

\subsubsection{Implementation and Validation} \label{normalization-implementation}

Our implementation processes the entire dataset through a unified preprocessing pipeline that integrates all five normalization steps. The pipeline includes several design features to ensure robustness and facilitate debugging:

\begin{itemize}
    \item \textbf{Smart skip logic}: Already-processed shapes are detected and skipped to enable efficient re-runs and iterative refinement of the pipeline
    \item \textbf{Step-by-step output}: For validation purposes, we save intermediate OBJ files after each normalization step:
    \begin{itemize}
        \item \texttt{00\_original.obj}: Original mesh from the dataset
        \item \texttt{01\_remeshed.obj}: After adaptive remeshing (only present if remeshing was applied)
        \item \texttt{02\_translated.obj}: After barycenter translation
        \item \texttt{03\_aligned.obj}: After PCA alignment
        \item \texttt{04\_flipped.obj}: After moment-based flipping
        \item \texttt{05\_scaled.obj}: Final normalized mesh
    \end{itemize}
    \item \textbf{Comprehensive validation}: Each processed shape undergoes extensive validation checks:
    \begin{itemize}
        \item Centering error analysis (distance from barycenter to origin)
        \item PCA eigenvalue ordering verification (ensuring $\lambda_1 \geq \lambda_2 \geq \lambda_3$)
        \item Moment test validation (confirming positive signed moments)
        \item Bounding box verification (confirming maximum extent equals 1.0)
        \item Cross-step consistency checks (ensuring each transformation preserves mesh topology)
    \end{itemize}
    \item \textbf{Enhanced numerical robustness}: The implementation uses area-weighted barycenter computation with fallback mechanisms for degenerate cases, two-pass recentering to handle numerical drift, and double-precision floating-point arithmetic throughout
\end{itemize}

The preprocessing pipeline ran to completion for all 2,483 shapes; while no processing terminated with a fatal error, a small subset (63) were flagged as mesh‑quality outliers and have been recorded for manual review and will be discussed in sub-section \ref{removing-outliers}. Validation metrics confirm that our implementation achieves high mathematical precision:

\begin{itemize}
    \item Mean centering error: $1.04 \times 10^{-14}$ (effectively zero within floating-point precision)
    \item Maximum centering error: $9.22 \times 10^{-13}$ (well within numerical tolerance)
    \item Mean scaling error: $3.18 \times 10^{-17}$ (negligible)
    \item Maximum scaling error: $2.22 \times 10^{-16}$ (within machine epsilon)
    \item 100\% compliance with eigenvalue ordering ($\lambda_1 \geq \lambda_2 \geq \lambda_3$)
    \item 100\% correct moment sign after flipping (all axes show positive moments)  
\end{itemize}

These results demonstrate that our implementation achieves the mathematical precision required for robust feature extraction. The normalized shapes are stored in the \texttt{UnifiedPreprocessed} directory, organized by category, with accompanying metadata files containing processing statistics and validation results for each shape.

\subsection{Step 3.2: 3D shape descriptors}
The purpose of this step is to transform normalized 3D meshes into discriminative descriptors that capture essential geometric characteristics. Each descriptor is designed to be invariant to translation, rotation, and scale, while still reflecting intrinsic shape differences. The following subsections present the mathematical foundations of the descriptors we implemented.

\subsubsection{Mesh preparation for feature extraction} \label{prepared}

Before computing descriptors, it is crucial to ensure that the normals of the faces are consistent and free of geometric defects. In particular, incomplete meshes with holes or inconsistent face windings can produce invalid volumes or surface areas. To address these issues, we apply a preprocessing routine consisting of two main steps: (1) filling holes and (2) orienting faces consistently.

\paragraph{Filling holes}
We want to fill holes because properties like volume and surface area are calculated using the faces. If some faces are missing, you do not want these descriptors to be incorrect. Boundary edges of a mesh are identified by counting the number of times each edge occurs in the face list. Edges that appear exactly once belong to the boundary of a hole. By traversing these edges, we group them into closed loops that represent the perimeters of the holes. For each hole loop, we compute its barycenter,
\begin{equation}
c_{\text{hole}} = \frac{1}{|E|} \sum_{(i,j) \in E} \frac{v_i + v_j}{2},
\end{equation}
where $E$ is the set of edges in the loop. This barycenter is added as a new vertex, and each boundary edge is connected to it to form a new triangular face. The process closes the hole while maintaining manifold connectivity. Although this procedure may simplify fine geometry, it is mostly good enough for the descriptors (volume, surface area) we want to compute.


\paragraph{Filling holes (limitations)} \label{limitations}
The barycentric triangulation approach for closing boundary loops is a pragmatic heuristic rather than a guaranteed, topology-preserving repair. Several failure modes can occur in practice:
\begin{itemize}[leftmargin=1.2em]
    \item \textbf{Non-manifold edges:} edges incident to three or more faces break the assumption that each interior edge is shared by exactly two faces; loop detection and subsequent triangulation will fail and holes using these edges will not be repaired.
    \item \textbf{Dangling/isolated edges:} multiple single (boundary) edges meeting at a vertex may not form a simple cycle, preventing a well-defined hole loop, or creating holes in a weird way. for example: two holes connecting at a single vertex can be repaired with a single 'plaster'.
    \item \textbf{Open or branching boundaries:} when boundary tracing encounters forks or dead-ends, no closed loop exists and triangulation will not complete.
    \item \textbf{Severe non-planarity:} highly warped boundary rims can yield skinny or inverted triangles when all edges are connected to a single barycenter in $\mathbb{R}^3$.
\end{itemize}
In our implementation, we treat loop construction as best-effort: if a consistent cycle cannot be recovered, the routine aborts for that component and leaves the boundary unchanged, logging a warning. After any successful fill, we run a cleanup pass that removes duplicate/degenerate faces and drops unreferenced vertices to mitigate newly introduced artifacts. Consequently, hole filling \emph{does not guarantee} watertightness. Rather, it increases the likelihood of obtaining a closed, consistently oriented surface suitable for downstream feature extraction while acknowledging the above limitations.

\paragraph{Consistent face orientation}
Meshes may contain inconsistently oriented faces, meaning that adjacent triangles along a shared edge traverse that edge in the same direction rather than opposite directions. This creates local inconsistencies in surface normal orientation. This is a problem for several descriptors such as the volume. To correct this, we perform a breadth-first traversal over faces: starting from an arbitrary seed face, all neighbors are visited through their shared edges. Whenever two faces share an edge with the same orientation, one is flipped by swapping two of its vertex indices:
\begin{equation}
(i, j, k) \;\;\mapsto\;\; (i, k, j).
\end{equation}
This ensures that the mesh forms a consistently oriented surface, suitable for all calculations of the descriptors. It does not matter if the normals are pointed inward or outward because for volume calculation we take the absolute value. We will get back to this in section \ref{volumee}.

\paragraph{Combined preparation}
The overall preparation pipeline can thus be summarized as:
\begin{enumerate}
    \item Detect boundary edges and close holes by barycentric triangulation.
    \item Remove degenerate and duplicate faces, and drop unused vertices.
    \item Traverse the mesh to enforce consistent face winding.
\end{enumerate}

This process produces meshes, which are then used as a more reliable input for feature extraction. Similar to the normalization steps (Subsection \ref{normalization-implementation}), we cached the output of this process as an OBJ file with the suffix \texttt{\_06\_fill\_holes\_and\_orientation.obj}, allowing users to interactively visualize the effects of this step using the same slider controller in the UI.

\subsubsection{Elementary descriptors}
Before introducing the descriptors, it is important to recall that all meshes in the dataset are first \emph{unified}. As described in section~\ref{normalization}, this includes alignment, scaling, and centering. In a second step, the meshes are prepared by filling holes and equalizing normals (see section~\ref{prepared}). As a result, every mesh is consistently placed inside the cube $[-0.5,0.5]^3$, ensuring that all descriptors are directly comparable across objects, independent of their original position, orientation, or scale.

\textbf{Feature Standardization} -
Each numeric descriptor was standardized using the z-score transform 
\begin{equation}
z = \frac{x - \mu}{\sigma},
\end{equation}
where $\mu$ and $\sigma$ are the column mean and population standard deviation, respectively. For each feature listed below, we included a combined figure, (Figures \ref{fig:std:volume}, \ref{fig:std:surface_area}, \ref{fig:std:compactness}, \ref{fig:std:rectangularity}, \ref{fig:std:diameter}, \ref{fig:std:convexity}, and \ref{fig:std:eccentricity}), which includes the original distribution (left column) and the z-score standardized distribution (right column), with histograms (top row), boxplots (middle row), and a compact table of summary statistics (bottom row). After successful standardization the transformed data have a mean near $0$ and a standard deviation near $1$; unusually large values of $\max |z|$ or low percentages within $|z| \leq 1, 2, 3$ indicate skewness or outliers that merit further inspection.

\paragraph{Volume} \label{volumee}
Several descriptors rely on a robust estimate of the enclosed volume. Following our implementation, we compute the signed volume per connected face component and then sum their absolute values:
\begin{equation}
V(M)=\sum_{c \in \mathcal{C}(M)} \left| \frac{1}{6} \sum_{(i,j,k)\in F_c} v_i \cdot \big( (v_j)\times (v_k) \big) \right|,
\end{equation}
where $\mathcal{C}(M)$ denotes the set of connected face components and $F_c$ the faces in component $c$. This per-component absolute value matches the BFS accumulation in our code and is robust to local orientation inconsistencies. The resulting $V(M)$ is then reused by compactness, convexity, and (volume-based) rectangularity.

\paragraph{Surface area}
The surface area describes the total extent of a mesh surface by summing the contributions of all triangular faces. It is defined as
\begin{equation}
A(M)=\tfrac{1}{2}\sum_{(i,j,k)\in F}\lVert (v_j-v_i)\times (v_k-v_i)\rVert.
\end{equation}
Intuitively, this value captures how much space the surface covers; shapes with large, detailed, or highly folded surfaces will have larger surface areas compared to simpler ones.

\paragraph{Surface area.} 
The visual progression in figure \ref{surface_area_scale} supports the correctness of the surface area computation. The object with the smallest surface area is a sword, while the object with the largest is a highly detailed building model with overlapping meshes. This ordering aligns with expectations and indicates that the descriptor reliably reflects variation in surface complexity across the dataset.

\begin{equation}

\end{equation}
A value close to $1$ indicates a sphere, the most compact shape, while larger values highlight shapes that are elongated, spiky, or irregular.

\paragraph{Rectangularity}
Rectangularity measures how well the shape \emph{fills} its oriented bounding box (OBB) in terms of volume. If the OBB has side lengths $(w,h,d)$, its volume is $V_{\mathrm{OBB}}=w\,h\,d$, and we define
\begin{equation}
\mathcal{R}(M)=\frac{V(M)}{V_{\mathrm{OBB}}(M)} \in (0,1].
\end{equation}
High values indicate that the object volumetrically occupies most of its OBB (box-like, chunky shapes), while low values signal thin or highly concave objects. Note that a \emph{thin} door for example still has a high value as the OBB box is also small.

The rectangularity scale in figure \ref{rectangularity_scale} appears consistent with geometric intuition. The flat palm tree exhibits low rectangularity because of its near zero volume, followed by the train and building models, which become progressively more rectangular in form. The values are higher than the theoretical (0, 1) range. This indicates that there might be a problem with the volume calculation for highly detailed meshes. Nevertheless, the trend across the images suggests that the descriptor accurately captures differences in overall shape.

A sphere yields $\varepsilon \approx 1$, while thin or elongated objects have much higher values, capturing their anisotropy.

\subsubsection{Shape property descriptors}
While the previously discussed global descriptors capture overall geometric properties of a mesh through single scalar values, they do not describe how these properties are distributed across the object. To address this limitation, we employ a set of statistical shape property descriptors: A3, D1, D2, D3, and D4, that capture local geometric relationships through large scale vertex sampling.  
Instead of returning a single measurement, each of these descriptors is represented as a normalized histogram that summarises the frequency of geometric relations such as angles, distances, triangle areas, or tetrahedron volumes. These descriptors provide a richer statistical characterization of shape structure by capturing not only the global extent but also the internal spatial variability of the geometry.  
Because they are based on random vertex sampling and operate on unified meshes, they are invariant to translation, rotation, and scale, and can effectively differentiate objects with similar overall size but distinct local geometric features.

\paragraph{A3: Angle distribution}
The A3 descriptor characterizes the distribution of angles formed by triplets of randomly selected vertices.  
For $(\mathbf{x}, \mathbf{y}, \mathbf{z}) \in \mathbf{V}^3$, the angle at vertex $\mathbf{x}$ is computed as

\begin{equation}
\theta = \arccos\!\left(\frac{(\mathbf{y}-\mathbf{x}) \cdot (\mathbf{z}-\mathbf{x})}
{\lVert \mathbf{y}-\mathbf{x} \rVert \, \lVert \mathbf{z}-\mathbf{x} \rVert}\right).
\end{equation}

We perform this computation for a total of $100{,}000$ samples, where each vertex is selected randomly with replacement.  
The resulting angle values are then aggregated into a frequency histogram.  
Before constructing the histogram, it was necessary to determine the appropriate range of the horizontal axis.  
The minimum possible angle was set to $0$, while for the maximum we initially considered the theoretical upper bound $\theta = \pi$.  
However, using the theoretical limit resulted in many empty bins in several histograms.  
To obtain a more informative distribution, we instead determined the empirical upper bound from the dataset by computing the $99$th percentile of all sampled angles and extending this value by an additional $10\%$ buffer.  
In practice, this adjusted upper limit was still close to the theoretical bound, at approximately $\theta \approx \pi$.  

Finally, the histogram was divided into $20$ bins, which provided a good balance between descriptive granularity and computational efficiency. Outlier values that fell above the range of the histogram were included in the last bin.

To verify that the computed A3 descriptor values were reasonable and informative, we analyzed the consistency of the resulting distributions both \emph{within} and \emph{between} object classes.  
Specifically, we plotted the per-shape angle distributions for $20$ representative classes, selected to be near the median in terms of the number of available shapes per class, ensuring a fair comparison across categories.  
The resulting per-class distributions are shown in Figure \ref{Fig-A3-class-comparison}.

The plots show the frequency distributions of sampled inter-vertex angles for $20$ object classes.  
For each class, the shapes exhibit relatively consistent intra-class distributions, while the overall profiles differ noticeably between classes.

First, despite some variability and occasional outliers, shapes within the same class tend to follow a similar distribution, suggesting that the descriptor is stable under intra-class variation.

Overall, these findings confirm that A3 provides a meaningful statistical representation of angular structure across 3D objects.


\paragraph{D1: Distance from barycenter to surface points}
The D1 descriptor quantifies how far the surface vertices of a shape lie from its mass barycenter.  
It is defined as the Euclidean distance between each sampled vertex $\mathbf{x}$ and the barycenter $\mathbf{b}(M)$:
\begin{equation}
d_1 = \lVert \mathbf{x} - \mathbf{b}(M) \rVert_2.
\end{equation}
In the implementation, all mesh vertices are used directly, corresponding to $n = |\mathbf{V}|$ iterations per mesh.  
For each vertex, this distance is computed and then grouped into a $20$-bin histogram spanning from $0$ to the empirically determined upper bound.
The resulting distribution describes how evenly mass is distributed around the barycenter.

Per-class histograms (Figure \ref{Fig-D1-class-comparison}) reveal that D1 captures differences in compactness:  
spherical or cubic shapes exhibit narrow, symmetric distributions around their mean distance, whereas elongated or branched shapes show flatter and wider profiles.

\begin{figure}[H]
\begin{center}
\includegraphics[width=1.0\columnwidth]{figures/D1_class_comparison.png}
\caption{\textbf{Per-class D1 distributions (each line represents one shape).}  
The distributions show distances from the barycenter to sampled vertices across $20$ object classes.  
Compact objects show narrow peaks, while extended or articulated ones have broader spreads, demonstrating that D1 effectively captures spatial dispersion.  
\label{Fig-D1-class-comparison}}
\end{center}
\end{figure}

While the general shapes of the D1 distributions differ noticeably between classes indicating that the descriptor successfully captures key geometric characteristics, there is also substantial variation within individual classes. This intra-class variability introduces a notable amount of noise into the distributions, which can lower the similarity scores among shapes belonging to the same category. A possible contributing factor is the remeshing process: uneven vertex sampling or local vertex density variations can significantly influence the computed distances from the barycenter, thereby affecting the resulting histogram shape.

\paragraph{D2: Distance between two random vertices}
The D2 descriptor characterises the distribution of distances between pairs of randomly selected vertices.  
For $(\mathbf{x}, \mathbf{y}) \in \mathbf{V}^2$, the distance is computed as
\begin{equation}
d_2 = \lVert \mathbf{x} - \mathbf{y} \rVert_2.
\end{equation}
In code, $100{,}000$ random pairs are generated using replacement, ensuring a diverse sampling even for meshes with fewer vertices.  
Each distance value is added to a 20-bin histogram within the range $[0, d_{\max}]$, where $d_{\max}$ was determined globally via the 99th percentile plus 10\% buffer.  

The resulting distributions (Figure \ref{Fig-D2-class-comparison}) reveal differences in spatial scale between object classes.  
Compact shapes concentrate distances near zero, while large or elongated shapes produce wider histograms extending toward the upper range.
D2 thus provides a global measure of spatial extent and object elongation, complementing D1 by comparing internal pairwise relationships rather than distances to the center.

\paragraph{D3: Square root of area of triangle given by three random vertices}
The D3 descriptor extends the concept of geometric sampling to areas of triangles defined by three randomly chosen vertices.  
For $(\mathbf{x}, \mathbf{y}, \mathbf{z}) \in \mathbf{V}^3$, the triangle area is computed as
\begin{equation}
A_\triangle = \tfrac{1}{2}\,\lVert (\mathbf{y}-\mathbf{x}) \times (\mathbf{z}-\mathbf{x}) \rVert.
\end{equation}
In the implementation, $100{,}000$ random triplets of vertices are sampled with replacement.  
Each triangle’s area is then square-rooted before histogramming to express it in length units and mitigate the effect of large outliers.  
The histogram again uses 20 bins over the range $[0, a_{\max}]$, with $a_{\max}$ empirically determined via the global 99th percentile plus 10\% margin.

Figure \ref{Fig-D3-class-comparison} shows per class D3 distributions, which reveal meaningful variation across object categories.  
Flat, planar shapes yield histograms skewed toward higher area values, while curved or finely detailed surfaces produce peaks near zero.

Within most classes, we again observe consistent trends across individual shapes, indicating that the descriptor captures meaningful structural information.  
For instance, elongated objects such as \emph{Bicycles} or \emph{Knives} tend to show a concentration of smaller area values, while more voluminous objects such as \emph{Cups} or \emph{Bottles} exhibit a broader spread.

The differences between class-level distributions again demonstrate that the D3 descriptor provides strong discriminative power, further supporting its suitability for shape comparison and retrieval tasks.

\paragraph{D4: Cube root of volume of tetrahedron formed by four random vertices}
The D4 descriptor generalises the previous sampling strategy to four vertices, measuring the volumes of tetrahedra they define.  
For $(\mathbf{w}, \mathbf{x}, \mathbf{y}, \mathbf{z}) \in \mathbf{V}^4$, the tetrahedron volume is computed as
\begin{equation}
V_\mathrm{tet} = \tfrac{1}{6}\,\big|\,(\mathbf{x}-\mathbf{w}) \cdot \big((\mathbf{y}-\mathbf{w}) \times (\mathbf{z}-\mathbf{w})\big)\,\big|.
\end{equation}
As in the implementation, $100{,}000$ random quadruples are sampled with replacement.  
The cube root of each volume is taken before histogramming to express values in consistent length units and reduce skew caused by large outliers.  
All values are grouped into a $20$-bin histogram over $[0, v_{\max}]$, where $v_{\max}$ is set to the global 99th percentile plus 10\% buffer.

Per-class D4 histograms (Figure \ref{Fig-D4-class-comparison}) reveal distinctive volumetric signatures:  
solid, compact shapes show broader, higher volume distributions, whereas thin or planar structures concentrate near zero.

\section{Step 4: Querying} \label{sec-Querying}
In this step, we implemented a content-based shape retrieval (CBSR) system that allows us to identify and rank shapes in the database based on their similarity to a given query shape. For each query, the system extracts the same set of features as described in the previous section, computes distances between the query and all database shapes, and returns the best-matching results. This step therefore forms the first end-to-end application of the feature extraction pipeline, integrating normalization, distance computation, and feature fusion.

The following subsections describe the main stages of this process: feature normalization, computation of descriptor-specific distances, normalization of the resulting distance matrices, and their combination into a single metric. We conclude with a short overview of the results.

\subsection{Normalizing Feature Values}
Before computing distances, we first normalize all extracted feature values to ensure comparability across descriptors. Since the global descriptors differ in their numeric ranges, we apply \emph{Z-score standardization} for each descriptor, transforming values such that the resulting feature distributions have zero mean and unit variance:
\begin{equation}
\mathbf{f}' = \frac{\mathbf{f} - \boldsymbol{\mu}_f}{\boldsymbol{\sigma}_f},
\end{equation}
where $\mathbf{f}$ denotes the original feature vector for a shape, and $\boldsymbol{\mu}_f$ and $\boldsymbol{\sigma}_f$ are the mean and standard deviation of that descriptor, computed across all shapes in the database.

For histogram-based descriptors, we convert the raw bin counts into \emph{frequency histograms}:
\begin{equation}
\mathbf{h}' = \frac{\mathbf{h}}{\sum_i h_i},
\end{equation}
ensuring that $\sum_i h'_i = 1$. This transformation makes the descriptors independent of sampling density and mesh resolution, allowing for meaningful cross-shape comparison. These normalized representations form the basis for all subsequent distance computations.

\subsection{Computing Distances for Individual Features}
Each descriptor provides an independent measure of similarity between shapes. For each pair of shapes $(a,b)$, we compute a descriptor-specific distance $D_k(a,b)$, where $k \in \{1, \dots, 11\}$ indexes the descriptors.

For scalar (global) descriptors, we use the standard Euclidean distance:
\begin{equation}
D_k(a,b) = \lVert \mathbf{f}'_{a,k} - \mathbf{f}'_{b,k} \rVert_2.
\end{equation}

For histogram-based descriptors, we employ the \emph{Earth Mover’s Distance} (EMD), which captures distributional dissimilarity by measuring the minimal work required to transform one histogram into another:
\begin{equation}
D_k(a,b) = \text{EMD}(\mathbf{h}'_{a,k}, \mathbf{h}'_{b,k}),
\end{equation}
where the EMD was implemented using the \texttt{wasserstein\_distance} function from \texttt{scipy.stats}.  

The result of this step is an $N \times N$ distance matrix $\mathbf{D}_k$ for each descriptor $k$, where $N$ is the number of shapes in the database and $(\mathbf{D}_k)_{ij} = D_k(i,j)$.

\subsection{Normalizing Distance Matrices}
Since the distance matrices $\mathbf{D}_k$ differ in their absolute ranges and distributions, we normalize them before combination to ensure that all descriptors contribute comparably. We implemented and tested three approaches:

\begin{enumerate}
    \item \textbf{Min-max normalization:}
    \begin{equation}
    \mathbf{D}'_k = \frac{\mathbf{D}_k - \min(\mathbf{D}_k)}{\max(\mathbf{D}_k) - \min(\mathbf{D}_k)}.
    \end{equation}

    \item \textbf{Z-score normalization:}
    \begin{equation}
    \mathbf{D}'_k = \frac{\mathbf{D}_k - \mu(\mathbf{D}_k)}{\sigma(\mathbf{D}_k)}.
    \end{equation}

    \item \textbf{Rank-based normalization:} each distance value $D_k(i,j)$ is replaced by its normalized rank within the corresponding descriptor matrix:
    \begin{equation}
    \mathbf{D}'_k(i,j) = \frac{\text{rank}(D_k(i,j))}{N^2}.
    \end{equation}
\end{enumerate}

We evaluated the three normalization schemes by measuring the mean average precision (MAP) at $K=10$ across the full database. The rank-based normalization achieved the best overall retrieval performance, followed by Z-score and min–max normalization. Therefore, rank-based normalization was used in all subsequent steps. Conceptually, it offers robustness to outliers and distribution skew, and it ensures that relative ordering rather than absolute scale determines the contribution of each descriptor.

Although our implementation assumes a fixed database size, rank-based normalization also lends itself well to handling queries from new, unseen shapes. 
In such cases, the distances between the query and all existing shapes could be computed and directly inserted into the existing ranking structure 
(e.g., by interpolating a fractional rank such as 345.5). This would allow the system to flexibly accommodate new shapes without recomputing the entire 
pairwise distance matrix. A full recomputation could then be performed periodically - such as after a certain number of new additions (e.g., 5–10\% of the 
original dataset) - to maintain overall consistency while keeping computational cost manageable.

\subsection{Combined Distance Metric}
After normalization, we integrate the individual descriptor distances into a single combined metric using a weighted sum:
\begin{equation}
D_{\text{combined}}(a,b) = \sum_{k=1}^{11} w_k \, \mathbf{D}'_k(a,b),
\end{equation}
where $w_k$ is the learned weight of descriptor $k$.  

To optimize these weights, we applied Bayesian optimization using the \emph{Optuna} framework with a Tree-structured Parzen Estimator (TPE) sampler. The objective function maximized the mean precision at $K=10$, with 200 optimization trials. Bayesian optimization was chosen for its ability to efficiently balance exploration and exploitation in a high-dimensional search space, yielding a set of weights that improved retrieval consistency across shape categories.

\subsection{Results}
A detailed quantitative evaluation of the system’s performance is presented in Section~\ref{sec-Evaluation}. 
Here, we briefly note that the implemented querying pipeline successfully integrates all preceding components - from 
feature extraction and normalization to distance computation and combination - into a unified retrieval framework. 
Preliminary qualitative tests confirmed that the system consistently returns visually and semantically similar shapes 
for a wide range of query inputs, indicating that the combined distance metric captures both fine-grained and 
category-level similarities. These observations are further substantiated by the quantitative results discussed in 
Section~\ref{sec-Evaluation}.

\section{Step 5: Scalability}
As the database grows in size, exhaustive pairwise distance computation for content-based shape retrieval becomes very computationally intensive. For our dataset we precomputed the distance from each shape to each other shape in the database. This however does not work when the database becomes too big or when shapes are queried which are not in the database. To enable efficient similarity search and intuitive exploration of high-dimensional feature spaces, we implemented two scalability mechanisms:
\begin{enumerate}
    \item \emph{K Nearest Neighbor (KNN)} engine for efficient $K$-nearest querying
    \item \emph{Dimensionality Reduction (DR)} engine based on t-SNE for low dimensional visual inspection of the feature space structure.
\end{enumerate}

\subsection{Step 5.1: K Nearest Neighbor Search}
\subsubsection{Methodology}
To enable efficient similarity querying, we implemented a $K$-Nearest Neighbour (KNN) search using a multidimensional tree (KD-Tree) structure. The process begins by extracting the feature vectors of all shapes in the database, forming a feature matrix $\mathbf{F} \in \mathbb{R}^{N \times D}$, where each row represents a mesh and each column corresponds to one feature descriptor. From this matrix, a KD-Tree is constructed, which hierarchically partitions the $D$-dimensional feature space to accelerate neighbour lookups.

When a query shape is submitted, we look up its feature vector $\mathbf{f}_q$ in the database. We could also compute its feature matrix within seconds if the shape is not in the database. The KNN algorithm then traverses the KD-Tree to identify candidate neighbours that are most likely to be close to $\mathbf{f}_q$ in feature space. For each candidate, the Euclidean distance is computed as
\begin{equation}
d(\mathbf{f}_q, \mathbf{f}_i) = \sqrt{\sum_{j=1}^{D} (f_{qj} - f_{ij})^2},
\end{equation}
where $\mathbf{f}_i$ denotes the feature vector of the $i$-th shape in the database.  
The algorithm then selects the $K$ shapes with the smallest distances to the query vector and returns them as the most similar matches. This KD-Tree–based approach substantially reduces the computational cost compared to exhaustive pairwise distance computation, especially when the database contains a large number of shapes.

\subsubsection{Limitations}
However, this KNN-based approach is not as sophisticated as the normal querying method described earlier in Section \ref{sec-Querying}. Since the individual feature components are not weighted according to their relative importance, and because the Earth Mover’s Distance (EMD) is not used for comparing histogram-based features, the retrieval accuracy is noticeably lower. We return to this issue in Step 6: Evaluation, where we discuss the quantitative evaluation of both methods.

\subsection{Step 5.2: Dimensionality Reduction for Visualization}
Dimensionality reduction is helpful in our pipeline because each shape is described by an 11-dimensional feature vector. While this high-dimensional data works well for computing distances and running the KNN search, it is difficult to interpret directly, and visualising relationships between shapes in 11 dimensions is not feasible. This will only become more challenging if we add more features in the future. To get an intuitive overview of how shapes relate to one another, we therefore reduce the feature space to two dimensions. This allows us to see how the shapes cluster, whether similar categories group together, and how well our descriptors capture the underlying structure of the dataset.

\subsubsection{Methodology}
To visualise the similarity relationships captured by the feature descriptors, we applied \textit{t}-Distributed Stochastic Neighbour Embedding (t-SNE) to project the high-dimensional feature space into two dimensions \cite{maaten2008visualizing}. In contrast to the KNN search, which operates on the raw feature vectors for efficient querying, t-SNE provides an interpretable visual representation of how shapes relate to one another in the overall database.

As input to t-SNE, we used the precomputed pairwise distance matrix $\mathbf{D} \in \mathbb{R}^{N \times N}$, where each entry $d_{ij}$ represents the Euclidean distance between the feature vectors of shapes $i$ and $j$. This ensures that the embedding directly reflects the distance relationships produced by our descriptors, rather than relying on the raw feature coordinates. 

The algorithm constructs a low-dimensional representation $\mathbf{Y} \in \mathbb{R}^{N \times 2}$ that preserves local neighbourhoods: shapes that are close in the high-dimensional space remain close in the two-dimensional projection. We experimented with several perplexity values (12, 25, 50, and 100) to observe their impact on the visual clustering. Broadly, higher perplexity values place more emphasis on global structure, whereas lower values prioritise local relationships. After testing, we selected a perplexity of $50$, as it provided the best balance between local and global cluster separation for our dataset.

Figures \ref{tsne-12} and \ref{tsne-25} illustrate the effect of using too small a perplexity value. This is particularly apparent in Figure \ref{tsne-12}, but also subtly visible in Figure \ref{tsne-25}. For instance, in the top yellow cluster, several blue points are dispersed throughout the cluster when using a perplexity of 25, indicating insufficient preservation of local structure. With a perplexity of 50, the blue cluster becomes more compact and better separated from the yellow cluster. Conversely, a perplexity of 100 as seen in Figure \ref{tsne-100} places too much emphasis on global structure, causing local clusters to become overly spread out. For example, the purple cluster on the left is clearly identifiable and coherent with a perplexity of 50, but becomes noticeably more diffuse when the perplexity is increased to 100.

\section{Step 6: Evaluation} \label{sec-Evaluation}

We evaluate the retrieval quality of our system by systematically querying each shape in the database and comparing the returned results against ground-truth class labels. Since we lack explicit similarity annotations, we use the semantic class labels provided with the dataset as a proxy for relevance: shapes belonging to the same class as the query are considered relevant, while shapes from different classes are deemed non-relevant. This evaluation compares our three distance matrix approaches and computes a range of binary-relevance metrics to assess both ranking quality and class-level discrimination performance.


\subsection{Evaluation Methodology}

Our evaluation framework follows a query-by-example paradigm where each shape in the database serves as a query input. We systemtically query all 2,438 shapes remaining after our outlier removal process. For a given query shape $Q$ with class label $C(Q)$, the retrieval system returns a sorted list of $n$ results $\{R_1, \ldots, R_n\}$ sorted by ascending distance from $Q$.

Ground-truth relevance is determined by class membership. We define the confusion matrix components as follows:
\begin{equation}
\text{TP} = |\{R_i : C(R_i) = C(Q), \, i \in \{1,\ldots,n\}\}|
\end{equation}
\begin{equation}
\text{FP} = |\{R_i : C(R_i) \neq C(Q), \, i \in \{1,\ldots,n\}\}| = n - \text{TP}
\end{equation}
\begin{equation}
\text{FN} = |\{S \in \text{DB} : C(S) = C(Q), S \notin \{R_1,\ldots,R_n\}\}|
\end{equation}
\begin{equation}
\text{TN} = |\{S \in \text{DB} : C(S) \neq C(Q), S \notin \{R_1,\ldots,R_n\}\}|
\end{equation}

where TP counts retrieved shapes from the same class as the query (true positives), FP counts retrieved shapes from different classes (false positives), FN counts relevant shapes not retrieved in the top-$n$ results (false negatives), and TN counts non-relevant shapes correctly excluded from the top-$n$ (true negatives).

This evaluation strategy ensures unbiased assessment by exhaustively querying every shape in the database, preventing selection bias that could arise from hand-picking query shapes. For our evaluation, we set the retrieval depth to $n=10$, reflecting a practical scenario where users examine the top results returned by the system.

We compare three descriptor aggregation approaches, We compare three descriptor aggregation approaches, each producing its own distance matrix for retrieval. All three approaches combine descriptor distances using empirically tuned weights in a weighted sum, but differ in how they preprocess the descriptor values before aggregation:
\begin{itemize}
    \item \textbf{MinMax Normalization}: Applies min-max scaling to normalize each descriptor's distances into the range $[0,1]$ before weighted aggregation.
    \item \textbf{Rank-Based Transformation}: Converts raw descriptor distances into ordinal rankings per query (lower rank = more similar) before weighted aggregation, producing a distance matrix robust to outliers and scale variations.
    \item \textbf{Standardization (Z-score)}: Applies z-score standardization to each descriptor's distances (zero mean, unit variance) before weighted aggregation.
\end{itemize}

Each approach generates a complete pairwise distance matrix between all shapes in the database, which is then used to rank retrieval results for every query. Metrics were computed at multiple aggregation levels to provide comprehensive insights into system performance. For each query, we calculated retrieval quality metrics based on the confusion matrix values (TP, FP, FN, TN). These per-query metrics were then averaged within each semantic class to obtain per-class performance measures, revealing which object categories are easily retrieved and which pose challenges. Finally, we computed macro-averaged metrics across all classes and overall query-level averages to characterize system-wide performance.

\subsection{Evaluation Metrics}

We selected a wide range of metrics to capture different aspects of retrieval quality, each emphasising distinct trade-offs between precision and recall. The metrics are formally defined as follows:

\paragraph{Accuracy}
Accuracy measures the proportion of correct predictions (both relevant and non-relevant) among all items:
\begin{equation}
\text{Accuracy} = \frac{\text{TP} + \text{TN}}{\text{TP} + \text{FP} + \text{FN} + \text{TN}} \in [0, 1]
\end{equation}

We include accuracy as a baseline metric due to its widespread use in classification and retrieval evaluation, enabling direct comparison between different approaches. Values range from 0 (all predictions incorrect) to 1 (all predictions correct). However, accuracy can be misleading in imbalanced datasets where the number of true negatives dominates, as is common in retrieval scenarios with many classes.

\paragraph{Precision}
Precision quantifies the fraction of retrieved items that are actually relevant:
\begin{equation}
\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}} \in [0, 1]
\end{equation}
Values range from 0 (no relevant items retrieved) to 1 (all retrieved items relevant). High precision indicates that the system returns few irrelevant results, which is crucial when users examine only the top-ranked items. Precision directly reflects the user's immediate experience with retrieval quality.

\paragraph{Recall (Sensitivity)}
Recall measures the fraction of relevant items successfully retrieved:
\begin{equation}
\text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}} \in [0, 1]
\end{equation}
Values range from 0 (no relevant items found) to 1 (all relevant items retrieved). High recall ensures comprehensive coverage of relevant shapes, though it may come at the cost of including more false positives. Recall is particularly important for exploratory search scenarios where completeness matters.

\paragraph{F1-Score}
The F1-Score provides a harmonic mean of precision and recall, balancing both metrics equally:
\begin{equation}
\text{F1-Score} = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} \in [0, 1]
\end{equation}
Values range from 0 (worst) to 1 (perfect precision and recall). This metric is especially valuable when we seek a single performance indicator that accounts for both false positives and false negatives. Unlike arithmetic means, the harmonic mean penalizes extreme imbalances between precision and recall.

\paragraph{Average Precision}
Average Precision (AP) computes the mean precision at each position where a relevant item is retrieved, providing a more nuanced view of ranking quality:
\begin{equation}
\text{AP} = \frac{1}{|\text{Relevant}|} \sum_{k=1}^{n} \text{Precision}(k) \cdot \text{rel}(k) \in [0, 1]
\end{equation}
where $\text{rel}(k)$ is an indicator function equaling 1 if the item at rank $k$ is relevant, and 0 otherwise. Values range from 0 (no relevant items or all at bottom ranks) to 1 (all relevant items at top ranks). This metric rewards systems that place relevant items at higher ranks, capturing the importance of result ordering beyond simple precision and recall.

\paragraph{ROC AUC}
The Area Under the Receiver Operating Characteristic curve (ROC AUC) evaluates the system's ability to discriminate between relevant and non-relevant shapes across all possible decision thresholds:
\begin{equation}
\text{ROC AUC} = \int_{0}^{1} \text{TPR}(t) \, d[\text{FPR}(t)] \in [0, 1]
\end{equation}
where TPR (True Positive Rate) equals recall and FPR (False Positive Rate) equals $\frac{\text{FP}}{\text{FP} + \text{TN}}$. Values range from 0 (perfect inverse discrimination) to 1 (perfect discrimination), with 0.5 indicating random performance. ROC AUC is particularly useful because it is threshold-independent and robust to class imbalance.

\paragraph{NDCG (Normalized Discounted Cumulative Gain)}
NDCG measures ranking quality by considering both relevance and position, assigning higher weights to relevant items appearing at top ranks:
\begin{equation}
\text{DCG@}k = \sum_{i=1}^{k} \frac{\text{rel}_i}{\log_2(i+1)}, \quad \text{NDCG@}k = \frac{\text{DCG@}k}{\text{IDCG@}k} \in [0, 1]
\end{equation}
where $\text{rel}_i$ is the relevance of the item at position $i$, and $\text{IDCG@}k$ represents the ideal DCG achieved by a perfect ranking. Values range from 0 (worst possible ranking) to 1 (ideal ranking). The logarithmic discount reflects diminishing user attention at lower ranks. We report both NDCG (Full), computed over all retrieved results, and NDCG@10, focusing on the top 10 results most likely to be examined by users.

\subsection{Experimental Results}

Figure \ref{fig:eval-macro-comparison} presents the macro-averaged performance across all categories for four evaluated retrieval approaches: three distance matrix methods with different normalization strategies and one KD-Tree-based KNN method. The rank-based transformation achieves the highest overall performance with an ROC AUC of 0.763 and Average Precision of 0.818, demonstrating superior discriminative ability. This approach's success can be attributed to its robustness against descriptor scale variations and outliers, as rank transformations inherently normalize different descriptor ranges. The standardization (z-score) approach shows competitive performance (ROC AUC: 0.738, Average Precision: 0.715), benefiting from the normalization of descriptor distances to zero mean and unit variance. The MinMax normalization approach yields slightly lower but still reasonable performance (ROC AUC: 0.723, Average Precision: 0.699), providing a baseline for comparison.

The KNN (Euclidean Distance) approach, which uses raw Euclidean distance on standardized features without weighted descriptor combination or Earth Mover's Distance for histograms, exhibits notably lower performance with an ROC AUC of 0.724 and Average Precision of 0.668. While the KNN method offers computational advantages through efficient KD-Tree indexing for fast approximate nearest neighbor search, its inferior retrieval quality highlights the importance of sophisticated distance aggregation strategies. The gap between KNN and rank-based approaches (0.039 difference in ROC AUC, 0.150 difference in Average Precision) demonstrates that treating all features equally with simple Euclidean distance fails to capture the relative importance of different geometric descriptors and the specialized comparison required for histogram-based shape distributions.

These improvements suggest that rank-based transformation helps reduce the impact of descriptor-specific biases that disproportionately affect challenging object categories.

\subsection{Discussion and Implications}

The evaluation results reveal several important insights for 3D shape retrieval systems. First, normalization strategy significantly impacts retrieval quality: the rank-based approach's consistent superiority across metrics demonstrates that addressing descriptor scale heterogeneity is crucial for multi-feature retrieval systems. The transformation of raw distances into ordinal rankings provides robustness against outliers and scale variations that arise from the diverse geometric properties captured by different shape descriptors. The comparison with the KNN approach further validates this observation: while KNN offers computational efficiency through KD-Tree indexing, its uniform treatment of all descriptors and reliance on simple Euclidean distance result in lower retrieval quality (ROC AUC: 0.724 vs 0.763 for rank-based), demonstrating that sophisticated distance aggregation strategies are essential for multi-descriptor retrieval systems.

Second, the gap between ROC AUC (0.72-0.76 for distance matrix methods, 0.724 for KNN) and precision at fixed cutoff (0.16-0.23) highlights an important distinction: our systems can effectively discriminate relevant from non-relevant shapes when considering the full ranking (as measured by AUC), but struggle to consistently place relevant items within the top-10 results. This gap is most pronounced for the KNN approach (precision: 0.194, recall: 0.271), suggesting that while approximate nearest neighbor methods provide reasonable global discrimination, they lack the refinement needed for high-quality top-k retrieval. This pattern suggests opportunities for improvement through ranking refinement techniques such as learning-to-rank approaches \cite{liu2009learning}, query-specific weight adaptation \cite{bhattacharjee2016query}, or hybrid strategies that combine KNN's computational efficiency for initial candidate generation with weighted distance refinement for final ranking.

Third, per-class performance analysis reveals that certain semantic categories are inherently more challenging for purely geometric approaches. Classes exhibiting high intra-class variation (e.g., Apartment, House) or sharing geometric properties with multiple categories may benefit from additional discriminative features beyond the shape descriptors employed here. Interestingly, the KNN approach demonstrates competitive or superior performance on specific geometrically coherent classes (e.g., Fish: 0.551 accuracy vs 0.482-0.624 for distance methods), suggesting that when feature space clusters are well-separated and compact, simple Euclidean distance suffices. However, for classes requiring nuanced geometric comparison (e.g., Humanoid, Bicycle, Sword), the weighted distance matrix approaches achieve substantially higher accuracy, confirming the value of descriptor-specific distance metrics and importance weighting. Potential enhancements could include part-based representations, structural graph descriptors, or learned deep features that capture semantic relationships beyond pure geometry.

Fourth, the moderate NDCG@10 values (0.22-0.26 across all methods) indicate substantial room for improvement in ranking quality. The KNN approach's NDCG@10 of 0.222 places it at the lower end of this range, slightly below the distance matrix methods (0.25-0.26), further confirming the ranking quality advantage of weighted descriptor combinations. Future work could explore re-ranking strategies based on user feedback, query expansion techniques, or hybrid approaches combining geometric descriptors with learned embeddings from shape classification networks. Additionally, adaptive weighting schemes that adjust descriptor importance based on query characteristics could bridge the gap between KNN's efficiency and rank-based methods' quality.

Despite these challenges, the overall performance demonstrates that content-based retrieval using geometric descriptors provides a solid foundation for 3D shape search. The rank-based approach's macro-averaged ROC AUC of 0.763 significantly exceeds random performance (0.5) and outperforms both the simpler KNN method (0.724) and alternative normalization strategies (MinMax: 0.723, Z-score: 0.738), confirming that our descriptor combinations capture meaningful geometric similarities that align with semantic categories. For practical applications, the system performs best for classes with distinctive geometric signatures and consistent intra-class structure, making it suitable for focused domain applications where shape categories exhibit strong geometric coherence. The trade-off between retrieval quality and computational efficiency, as exemplified by the comparison between rank-based transformation and KNN approaches, offers practitioners flexibility in choosing appropriate methods based on application-specific requirements: weighted distance matrices for quality-critical applications, and KNN-based approximate search for large-scale databases where query speed is paramount.

\subsection{Query Examples}

To provide qualitative insights into the retrieval performance beyond aggregate metrics, we conducted a systematic analysis of query results across different performance tiers. Based on the per-class F1-scores shown in Figure \ref{fig:eval-f1score-perclass}, we divided the 69 categories into three performance categories: high-performing classes (top tertile, F1 $>$ 0.50), medium-performing classes (middle tertile, 0.25 $<$ F1 $<$ 0.50), and low-performing classes (bottom tertile, F1 $<$ 0.25). From each tier, we selected three representative classes and identified the query shapes within those classes that achieved the highest retrieval accuracy under the rank-based transformation approach. This selection strategy ensures that the visualized examples represent the best-case performance achievable within each difficulty category, providing upper-bound insights into retrieval quality.

For each selected query shape, we generated comparative visualizations showing the top-5 most similar shapes retrieved by all four matching approaches: KNN with Euclidean distance, MinMax normalization, Rank-based transformation, and Z-score standardization. Each retrieved shape is rendered as a 3D mesh with color-coded visual feedback: green coloring denotes shapes belonging to the same semantic class as the query (true positives), while red coloring indicates shapes from different classes (false positives). This color-coding scheme enables immediate visual assessment of precision within the top-5 results. Figures \ref{fig:query_high_1}-\ref{fig:query_high_3} present examples from the high-performance tier, Figures \ref{fig:query_medium_1}-\ref{fig:query_medium_3} show medium-performance cases, and Figures \ref{fig:query_low_1}-\ref{fig:query_low_3} illustrate low-performance scenarios.

The visualizations reveal distinct patterns that corroborate and explain the quantitative performance differences observed in Figure \ref{fig:eval-f1score-perclass}. Classes in the high-performance tier, such as Bicycle ($F1$ = 0.724), HumanHead ($F1$ = 0.837), and Humanoid ($F1$ = 0.694), display predominantly green-colored retrieved shapes across all four approaches. This consistency indicates that these classes possess distinctive geometric signatures that are robustly captured by our shape descriptors. For instance, bicycles are characterized by their open frame structure with circular wheels, while human heads exhibit recognizable proportions with facial feature arrangements. These classes demonstrate that when intra-class geometric coherence is high and inter-class separability is strong, even different normalization strategies converge on similar correct retrievals.

In contrast, classes in the low-performance tier, represented by Sign ($F1$ = 0.118), Vase ($F1$ = 0.127), and FloorLamp ($F1$ = 0.143), display predominantly red-colored retrieved shapes even for the best-performing queries within those categories. This systematic failure across all approaches reveals fundamental limitations in using purely geometric descriptors for certain semantic categories. Signs exemplify extreme intra-class variation, ranging from simple flat rectangular panels to complex three-dimensional structures with irregular geometries, making it difficult to identify a consistent geometric signature. Vases illustrate the challenge of inter-class confusion: their cylindrical geometry with varying height-to-width ratios overlaps significantly with cups, bottles, and lamp bases, leading to semantically incorrect but geometrically plausible retrievals. These cases suggest that low F1-scores often reflect inherent ambiguity in the geometric feature space rather than deficiencies in the distance computation methods.

Classes in the medium-performance tier, such as Violin ($F1$ = 0.293), Monoplane ($F1$ = 0.292), and Rocket ($F1$ = 0.267), display mixed retrieval quality with both correct and incorrect matches appearing in the top-5 results. The partial success observed in these cases suggests that retrieval performance is query-dependent: some shapes within these classes possess sufficiently distinctive geometric configurations to enable accurate retrieval, while others share geometric properties with multiple categories. For example, violins may be confused with other string instruments due to similar curved body shapes, while rockets and missiles share elongated cylindrical geometries that lead to cross-class confusion. This variability indicates that medium-tier classes often represent semantically coherent but geometrically diverse categories, where descriptor-based retrieval succeeds for prototypical shapes but struggles with atypical or boundary cases.

Across all performance tiers, we observe that the rank-based transformation approach consistently achieves competitive or superior results compared to alternative normalization strategies, with several queries showing perfect or near-perfect top-5 accuracy. The KNN approach, while computationally efficient, occasionally retrieves geometrically similar shapes from incorrect semantic categories, highlighting the trade-off between query speed and retrieval accuracy inherent in approximate nearest neighbor methods. Overall, these visualizations demonstrate that retrieval quality is determined by a complex interplay between intra-class geometric consistency, inter-class geometric distinctiveness, and the discriminative power of the chosen shape descriptors.

\subsection{Future Work}

While the current system demonstrates solid retrieval performance on geometrically distinctive shape classes, several extensions could enhance both accuracy and usability for practical deployment.

\begin{itemize}
\item \textbf{Enhanced Similarity Functions:} The current distance computation relies on manually designed geometric descriptors combined through weighted aggregation. Future work could explore learned similarity functions that automatically discover discriminative feature combinations for specific shape categories. Deep metric learning approaches \cite{schroff2015facenet} could learn embedding spaces where semantically similar shapes cluster more tightly than geometrically similar but semantically different objects. Additionally, incorporating context-aware weighting schemes that adapt descriptor importance based on query shape characteristics could improve retrieval quality for challenging categories exhibiting high intra-class variation. 

\item \textbf{User Interface Performance Optimization:} The current web-based interface experiences latency when rendering complex 3D meshes and computing real-time similarity searches across the full database. Performance improvements could include progressive mesh simplification for faster rendering, spatial indexing structures for accelerated nearest neighbor queries, and result caching strategies to avoid redundant computations. Implementing server-side rendering with lightweight client-side previews would reduce bandwidth requirements for remote access. Additionally, adopting WebGL-based visualization libraries could leverage GPU acceleration for smoother interaction with high-resolution shape models.

\item \textbf{On-the-Fly Shape Integration:} Currently, the system operates on a fixed database requiring offline preprocessing for feature extraction and distance matrix computation. Extending the system to support dynamic shape insertion would enable users to query custom shapes without full database recomputation. This requires developing incremental feature extraction pipelines that compute descriptors for new shapes in real-time, partial distance matrix updates that insert new shape similarities without recalculating all pairwise distances, and adaptive KD-Tree rebalancing for efficient KNN queries on evolving datasets. Such capabilities would transform the system from a static retrieval tool into an interactive shape analysis platform suitable for iterative design workflows and exploratory modeling tasks.
\end{itemize}
