\section{Introduction} \label{sec:introduction}

Content-based 3D shape retrieval addresses the fundamental challenge of identifying similar three-dimensional objects within large databases using geometric and topological properties rather than textual metadata. Given a query shape, such systems must rank database entries by similarity and return the most relevant matches, requiring sophisticated understanding of shape characteristics across different scales and representations.

In this work, we implement a complete 3D shape retrieval system using a collection of triangular meshes spanning diverse semantic categories and geometric complexities. Originating from the Princeton Shape Benchmark \cite{shilane2004princeton}, the dataset includes everyday objects, vehicles, buildings, tools, and animal models, offering a broad test-suite for evaluating retrieval accuracy and computational performance.

The system was developed through six main stages: data visualization and preprocessing, geometric normalization, feature extraction, similarity metric design, spatial indexing, and performance evaluation. Each stage builds on the previous to form an end-to-end pipeline that allows querying a shape and retrieving the most similar objects from the database. The following sections describe these stages in detail and present the results of our evaluation. The full source code to our project is available via \href{https://github.com/BarGinger/MultimediaRetrieval.git}{GitHub}.

\section{Dataset}
For this multimedia retrieval assignment, we utilized a comprehensive 3D shape database containing diverse geometric objects organized into semantic categories. The database comprises shapes sourced from the Princeton Shape Benchmark \cite{shilane2004princeton}, offering a diverse range of 3D mesh objects suitable for content-based shape retrieval research. The complete data set used can be found \href{https://github.com/BarGinger/MultimediaRetrieval/tree/4489fb12a23cc732ef120aa5b21304f50ea49b45/Datasets/Data}{here}.

The dataset comprises 2,483 3D mesh objects distributed across 69 distinct semantic categories, ranging from everyday objects like chairs, tables, and cups to more specialized items such as aircraft, musical instruments, and architectural elements. This diversity ensures comprehensive coverage of different shape characteristics, geometric complexities, and semantic domains essential for robust retrieval system evaluation. The category distribution ranges from 15 to 143 shapes per category, with an average of 36.0 shapes per category and a median of 27 shapes per category.

Each shape in the database is associated with a class label corresponding to its semantic category, derived from the original benchmark collections' folder organization structure. These class labels serve as ground truth for evaluation purposes in our content-based shape retrieval system. The shapes are stored in OBJ format \cite{bourke1999obj}, a widely-used standard for 3D mesh representation, containing vertex coordinates, face connectivity information, and associated geometric metadata.

The collection, as detailed in Table \ref{tab:dataset_composition}, exhibits significant variety in geometric complexity, with shapes averaging 5,908 vertices and 12,110 faces per object. This natural variation in mesh resolution and complexity provides an excellent testbed for evaluating the robustness and effectiveness of different shape descriptors and retrieval algorithms across objects of varying geometric detail and structural characteristics. Given the inherent variability in mesh resolution and geometric representation across the collection, a systematic preprocessing and normalization pipeline was essential to ensure consistent feature extraction and reliable retrieval performance. The comprehensive details of this multi-step process are presented in Sections \ref{step2} and \ref{step3}.

\section{Mathematical Notations}
The following notations are used throughout this report:

\begin{itemize}
    \item $V = \{v_1, v_2, \ldots, v_n\}$: Set of mesh vertices, where each $v_i \in \mathbb{R}^3$.
    \item $F = \{f_1, f_2, \ldots, f_m\}$: Set of mesh faces, where each $f_j$ is a sequence of vertex indices.
    \item $M = (V, F)$: A mesh, consisting of vertices and faces.
    \item $\mathbf{n}_f$: The normal vector of face $f$.
    \item $\mathbf{n}_i$: The normal vector at vertex $v_i$, computed as the average of adjacent face normals.
    \item $E$: Set of unique mesh edges, extracted from the faces.
    \item $c \in \mathcal{C}$: The semantic class label of the mesh, where $\mathcal{C}$ is the set of all possible classes.
    \item $|V| = n$: The number of vertices in the mesh.
    \item $|F| = m$: The number of faces in the mesh.
    \item $\tau(f_j)$: The type of face $f_j$ (triangle, quadrilateral, or polygon).
    \item $\mathcal{T}(M) = \{\tau(f_j) \mid f_j \in F\}$: The set of face types present in the mesh.
    \item $B(M) = [\mathbf{v}_{\min}, \mathbf{v}_{\max}]$: The axis-aligned bounding box of $M$, where 
          $\mathbf{v}_{\min} = (\min_i v_i^x, \min_i v_i^y, \min_i v_i^z)$ and 
          $\mathbf{v}_{\max} = (\max_i v_i^x, \max_i v_i^y, \max_i v_i^z)$.
    \item $\mathbf{s} = (s_x, s_y, s_z)$: Side lengths of the bounding box, with $s_x = v_{\max}^x - v_{\min}^x$, etc.
    \item $s_{\max} = \max(s_x, s_y, s_z)$: Longest side length of the bounding box.
    \item $\alpha = \tfrac{1}{s_{\max}}$: Uniform scaling factor ensuring that the longest side of the bounding box is mapped to $1.0$.
    \item $\mathbf{b}(M)$: The mass barycenter of mesh $M$, computed as the area-weighted average of triangle centroids.
\end{itemize}

The viewer app was developed as a web-based application, using Dash \cite{dash} to manage reactive interactions and Plotly \cite{plotly} to provide efficient 3D visualization capabilities. The selection of this technology stack was guided by three requirements: 
\begin{enumerate}

    \item Cross-platform accessibility without the need for specialized 3D software.

\section{Step 1: Read and view the data}

Effective retrieval requires a clear understanding of the dataset at hand. To address this, our system begins with the development of an exploration and visualization framework tailored to 3D meshes. The following subsections provide a detailed breakdown of the application's implementation.

The purpose of this stage is to establish a comprehensive environment for systematic analysis of the mesh datasets. Interactive visualization is a central component in multimedia retrieval, as it enables researchers to assess data distributions, identify potential preprocessing challenges, and validate algorithmic decisions.

\subsection{Data Format Processing and Geometric Representation}

Our system processes triangular mesh data stored in the Wavefront OBJ format, which has become the de facto standard for 3D model interchange due to its simplicity and widespread software support \cite{bourke1999obj}. The OBJ format represents 3D objects through two primary components: vertex coordinates defining spatial geometry and face definitions specifying triangular connectivity.

We implemented a custom \texttt{OBJParser} class that addresses several technical challenges inherent in OBJ processing:

\begin{itemize}
    \item \textbf{Index Convention Translation}: OBJ files use 1-based indexing while NumPy arrays require 0-based
    \item \textbf{Polygon Triangulation}: Automatic conversion of quad faces to triangles through diagonal splitting, ensuring consistent triangular mesh representation required for downstream processing
    \item \textbf{Robust Parsing}: Error handling for malformed geometry definitions and missing vertex references
\end{itemize}

The parser extracts vertex coordinates $V = \{v_1, v_2, \ldots, v_n\}$ where $v_i \in \mathbb{R}^3$ and face connectivity $F = \{f_1, f_2, \ldots, f_m\}$ where each face $f_j$ contains three vertex indices, forming the fundamental mesh representation $M = (V, F)$ used throughout our retrieval pipeline.

\subsection{Interactive Visualization System}

The visualization component leverages Plotly's WebGL-based 3D rendering engine, which provides hardware-accelerated graphics suitable for real-time interaction with complex meshes \cite{qin2021web}. Our implementation incorporates several advanced rendering techniques:

To visualize 3D shapes in our web application, we use the textit{Mesh3d} object from the Plotly Graph Objects library \cite{go}. This tool allows us to render interactive 3D meshes directly in the browser, providing smooth rotation, zooming, and lighting effects. By leveraging Plotly's capabilities, we can display complex surfaces and wireframes in a user-friendly way.

\subsubsection{Wireframe Edge Visualization}

Our optional wireframe overlay uses an efficient edge extraction method that avoids duplicate edges by storing them in a set. For each face $f$ in the set of faces $F$, we iterate over its edges. Each edge is represented by a pair of vertex indices, sorted to ensure consistency. We add each sorted edge to the set $E$, which automatically removes duplicates.

This set-based approach guarantees $O(F)$ complexity for edge extraction, where $F$ is the number of faces. The resulting set contains $E$ unique edges. This significantly reduces rendering overhead compared to naive enumeration of all face edges~\cite[pp.~17--19]{botsch2010polygon}.

\begin{algorithm}[H]
\SetAlgoLined
\KwIn{Set of faces $F$ (each face is a list of vertex indices)}
\KwOut{Set of unique edges $E$}
$E \gets \emptyset$\tcp*[l]{Initialize empty edge set}
\ForEach{face $f \in F$}{
    \For{$i \gets 0$ \KwTo $|f|-1$}{
        $v_1 \gets f[i]$\;
        $v_2 \gets f[(i+1) \bmod |f|]$\;
        $edge \gets \text{sort}(v_1, v_2)$\tcp*[l]{Sort vertex indices for consistency}
        $E \gets E \cup \{edge\}$\tcp*[l]{Add edge to set (deduplication)}
    }
}
\Return{$E$}
\caption{Efficient Wireframe Edge Extraction}
\end{algorithm}

\section{Step 2: Preprocessing and cleaning} \label{step2}
The dataset contains a large variety of 3D objects that differ significantly in complexity, resolution and overall quality. Before features can be reliably extracted and used for retrieval, it is essential to ensure that all shapes satisfy certain quality requirements. Poorly sampled meshes, inconsistent scaling, or misaligned objects may bias the descriptors extracted later on, which in turn reduces the effectiveness and fairness of the retrieval system.

In this section, we analyze the structural characteristics of all shapes in the database and identify common irregularities such as extreme outliers in the number of vertices and faces, as well as variations in scale and positioning. By collecting global statistics over the dataset, we obtain a better understanding of its variability and can determine which objects require resampling or refinement.

Next, we apply a set of preprocessing operations to improve dataset consistency. These operations include mesh simplification for overly large shapes, refinement for undersampled ones, and normalization to standardize the position and scale of each object. The resulting database forms a more balanced and homogeneous foundation for the subsequent feature extraction stage, ensuring that differences in descriptors reflect meaningful shape characteristics rather than artifacts of the raw input data.

\subsection{Step 2.1: Analyzing a single shape}
Before starting the preprocessing and cleaning of the dataset, we first obtain an overview of the initial variability of the objects. 
For this purpose, we implemented a simple analysis tool that reports, for each shape $M = (V, F)$, the following properties:
\begin{itemize}
    \item The semantic class label $c \in \mathcal{C}$ of the shape.
    \item The number of vertices $|V|$ and the number of faces $|F|$.
    \item The set of face types $\mathcal{T}(M)$, which indicates whether the shape consists of only triangles, only quadrilaterals, or a mixture of polygon types.
    \item The axis-aligned bounding box $B(M) = [\mathbf{v}_{\min}, \mathbf{v}_{\max}]$, defined by the minimum and maximum coordinates among all vertices.
\end{itemize}
This information provides a concise summary of the raw dataset characteristics and highlights potential sources of variability that may need to be addressed in subsequent preprocessing steps.

The tool operates by iterating over all files in the dataset in \texttt{.obj} format. In this format, each line encodes either a vertex position (\texttt{v}), a vertex normal (\texttt{vn}), or a face (\texttt{f}). During parsing, each vertex is added to the set $V$, and each face to the set $F$, while ignoring additional attributes such as normals and texture coordinates. Once all lines have been processed, we directly obtain $|V|$ and $|F|$. The bounding box $B(M)$ is computed by taking the coordinate-wise minima and maxima of the vertices. Face types are determined by checking the number of vertices in each face, distinguishing between triangles, quadrilaterals, and higher-order polygons. 

The extracted statistics are written to a comma-separated values (\texttt{CSV}) file, producing one record per shape. In the next step, we will aggregate these records to obtain statistics over the entire dataset.

\subsection{Step 2.3. Resampling outliers} \label{step2.3}
%Why remesh?%
From the obtained statistics it has become clear that the dataset contains a wide variety of shapes. To ensure fair and unbiased feature extraction and object retrieval, it is necessary to reduce the influence of extreme outliers in terms of vertex count. For this reason, we apply a remeshing step that regularizes the mesh resolution across the dataset. This ensures that all shapes are represented at a comparable level of detail, making subsequent analysis and retrieval more consistent and reliable.

%Target vertex count, why this?%
For the remeshing step, it is necessary to specify a target resolution in terms of vertex count. We chose a nominal target of $7{,}500$ vertices, which offers a good compromise between preserving geometric detail and maintaining manageable processing times. Because it is often impractical to achieve exactly this number of vertices, we allow a tolerance range of $5{,}000$ to $10{,}000$ vertices. Remeshing therefore stops once the mesh falls within this range, ensuring both consistency across the dataset and robustness of the preprocessing pipeline.

%What tools were used?%
The remeshing procedure was implemented using \textbf{Open3D} \cite{Zhou2018} (version $\geq$0.18), an open-source library for 3D data processing. Open3D provides efficient tools for handling triangle meshes, including vertex and triangle access, mesh cleaning, simplification, and subdivision. Its functions for \emph{quadric-based decimation} and \emph{midpoint subdivision} were used to adjust mesh resolution while preserving the shape of the geometry. Additionally, \textbf{NumPy} \cite{harris2020array} was employed for numerical computations, nearest-neighbor searches, and vertex reprojection.

The goal of the remeshing step is to reduce the variation in mesh resolution across the dataset and limit the influence of outlier meshes. The algorithm works as follows:

\begin{enumerate}
    \item \textbf{Vertex Count Check:} Each mesh is first checked against the target vertex range of 5,000 to 10,000 vertices (nominal target: 7,500). Meshes that are already within this range are copied without modification.

    \item \textbf{Upsampling:} Meshes with fewer vertices than the minimum threshold are increased in resolution using a \emph{feature-preserving midpoint subdivision}. New vertices are projected toward local planes or neighborhood centroids to maintain surface features and prevent excessive smoothing. This process is repeated in multiple passes until the mesh reaches the desired resolution.

    \item \textbf{Downsampling:} Meshes exceeding the maximum vertex threshold are simplified using \emph{quadric-based decimation}. The reduction is applied iteratively in multiple passes, with the reduction ratio adapted depending on how far the mesh is from the target. If the decimation stalls, a more aggressive pass is applied to ensure the mesh falls within the target range.

    \item \textbf{Feature Preservation:} Sharp edges and important geometric features are identified based on dihedral angles between adjacent faces. During subdivision and decimation, these features guide the placement of new vertices and the removal of faces to retain the overall shape. Planar regions are preserved by blending vertex positions toward fitted local planes when possible.

    \item \textbf{Fallback and Robustness:} In rare cases where standard upsampling fails, a single subdivision pass followed by light decimation is used. Mesh cleaning operations, such as removal of degenerate triangles and duplicated vertices, are applied throughout to maintain mesh quality.
\end{enumerate}

This approach ensures that all meshes in the dataset have a comparable number of vertices while keeping their geometric features intact, which facilitates consistent feature extraction and object retrieval.

\subsection{Step 2.5: Normalizing shapes} \label{step2.5}
%Explain why further normalization is needed%
Having reduced the variance in mesh resolution, we next address other characteristics of the dataset that require normalization. In this substep, we translate each object so that its barycenter is positioned at the origin $(0,0,0)$, and uniformly scale it to fit within a unit cube.

To achieve this, we first calculate the mass barycenter of the mesh, which corresponds to the center of mass under the assumption that each face has uniform density. 
Instead of simply averaging all vertices, we compute an area-weighted average of the centroids of all triangular faces.

For a triangular mesh $M = (V, F)$ with vertices $V = \{v_1, \dots, v_n\}$, $v_i \in \mathbb{R}^3$, and faces 
$F = \{f_1, \dots, f_m\}$, each face $f_j = (v_{j1}, v_{j2}, v_{j3})$ contributes as follows:

\begin{equation}
c(f_j) = \frac{1}{3}\big(v_{j1} + v_{j2} + v_{j3}\big)
\end{equation}

\begin{equation}
A(f_j) = \frac{1}{2}\,\big\lVert (v_{j2} - v_{j1}) \times (v_{j3} - v_{j1}) \big\rVert
\end{equation}

where $c(f_j)$ is the centroid of face $f_j$ and $A(f_j)$ its area.  
The mass barycenter of the full mesh is then given by

\begin{equation}
b(M) = \frac{\sum_{j=1}^m A(f_j)\,c(f_j)}{\sum_{j=1}^m A(f_j)}
\end{equation}

In the degenerate case where $\sum_{j=1}^m A(f_j) = 0$ (e.g., if no valid faces are present), 
we fall back to the simple geometric centroid of the vertices:

\begin{equation}
b(M) = \frac{1}{n}\sum_{i=1}^n v_i
\end{equation}

This ensures a well-defined barycenter for all meshes in the dataset.

We have calculated the offset of the barycenter to the origin of the space before applying the translation normalization. The results can be seen in Figure \ref{Fig-Histogram-Barycenter-Before}. We observe a large variance in this offset over the dataset.

Following the translation, we normalize the scale of each mesh. Formally, we compute the axis-aligned bounding box of a mesh $M$, defined as

\begin{equation}
B(M) = [\mathbf{v}_{\min}, \mathbf{v}_{\max}]
\end{equation}

where

\begin{equation}
\mathbf{v}_{\min} = (\min_i v_i^x, \min_i v_i^y, \min_i v_i^z), \quad
\mathbf{v}_{\max} = (\max_i v_i^x, \max_i v_i^y, \max_i v_i^z)
\end{equation}

We then determine the bounding box side lengths

\begin{equation}
\mathbf{s} = \mathbf{v}_{\max} - \mathbf{v}_{\min}
\end{equation}

and take the largest dimension 

\begin{equation}
s_{\max} = \max(s_x, s_y, s_z)
\end{equation}

To enforce uniform scaling, each vertex is scaled by the factor

\begin{equation}
\alpha = \frac{1}{s_{\max}}
\end{equation}

such that the longest side of the bounding box is mapped to length $1.0$. This guarantees that every object is contained within a unit cube $[-0.5, 0.5]^3$.

\section{Step 3: Feature extraction} \label{step3}

Feature extraction constitutes a critical component of content-based shape retrieval, transforming raw geometric data into compact, discriminative descriptors that capture essential shape characteristics. The effectiveness of any retrieval system fundamentally depends on the quality and robustness of these extracted features, which must be invariant to irrelevant transformations while remaining sensitive to meaningful geometric differences.

This stage consists of two principal components: normalization and descriptor computation. Before features can be meaningfully extracted and compared, all shapes must undergo a rigorous normalization pipeline to eliminate variations in position, orientation, scale, and mesh resolution. This preprocessing ensures that extracted features reflect intrinsic shape properties rather than arbitrary differences in how the meshes were originally authored or captured.

Following normalization, we compute a comprehensive set of shape descriptors spanning both global properties and distribution-based features. Global properties include surface area, volume, and eccentricity, which characterize the overall shape structure. Distribution-based features capture geometric relationships through statistical sampling: the angle between three random points, the distance from barycenter to a random point, the area of triangles formed by three random points, the volume of tetrahedra formed by four random points, and the distance between two random points. These descriptors are designed to capture complementary aspects of shape geometry, providing a rich feature space for subsequent similarity matching.

The implementation of this stage required careful attention to numerical stability, computational efficiency, and compliance with established best practices. We leverage an enhanced mesh class for normalization operations and a dedicated feature extraction class for descriptor computation, with comprehensive validation at each step to ensure correctness.

\subsection{Step 3.1: Full normalization}

Normalization serves to eliminate extrinsic variations among shapes, ensuring that subsequent feature extraction focuses on intrinsic geometric properties. Our implementation follows a comprehensive five-step normalization pipeline executed in a specific order to maintain mathematical correctness: remeshing, translation, alignment (pose), flipping (orientation), and scaling.

\subsubsection{Pipeline Overview}

The normalization process builds upon the remeshing procedure described in Section \ref{step2}, which standardizes mesh resolution across the dataset to a target range of 5,000 to 10,000 vertices. This remeshing step forms the foundation of our preprocessing pipeline, ensuring that all shapes have comparable geometric complexity before applying geometric transformations. The complete pipeline processes the shapes through the following sequence:

\begin{enumerate}
    \item \textbf{Remeshing}: Standardize mesh resolution (as detailed in \ref{step2.3}, \nameref{step2.3})
    \item \textbf{Translation}: Center the shape at the coordinate origin
    \item \textbf{Alignment}: Rotate to align principal axes with coordinate axes
    \item \textbf{Flipping}: Ensure consistent orientation across similar shapes
    \item \textbf{Scaling}: Fit within a unit bounding box
\end{enumerate}

Each transformation is applied sequentially, with the output of one step serving as input to the next. This order is critical for mathematical correctness. Centering must precede alignment because PCA requires centered data to compute meaningful principal axes. Alignment must precede flipping to establish a consistent reference frame before determining orientation. Scaling must occur last to preserve the geometric relationships established by the previous transformations.

\subsubsection{Mathematical Framework}

Let $M = (V, F)$ represent a triangular mesh with vertices $V = \{v_1, \ldots, v_n\}$ where $v_i \in \mathbb{R}^3$ and faces $F$. After remeshing, the normalization pipeline applies a sequence of transformations:

\begin{equation}
V' = (T_4 \circ T_3 \circ T_2 \circ T_1)(V)
\end{equation}

where $T_1, T_2, T_3, T_4$ represent translation, alignment, flipping, and scaling transformations, respectively, and the composition $(T_4 \circ T_3 \circ T_2 \circ T_1)(V) = T_4(T_3(T_2(T_1(V))))$ indicates that transformations are applied sequentially from right to left.

\textbf{Step 1: Remeshing.} As described in Subsection \ref{step2.3}, \nameref{step2.3}, each mesh is first evaluated against a target vertex range of 5,000 to 10,000 vertices. Meshes already within this acceptable range are identified and copied without modification, avoiding unnecessary processing that could introduce artifacts or degrade geometric quality. Only meshes falling outside this range undergo adaptive subdivision or decimation to reach the target resolution. This conditional processing ensures that all shapes are represented at comparable levels of detail while preserving the quality of already well-sampled meshes. The approach prevents high-resolution meshes from dominating feature computations and ensures low-resolution meshes have sufficient geometric information, without unnecessarily reprocessing shapes that already meet the quality criteria.

\textbf{Step 2: Translation (Centering).} The remeshed shape is centered at the coordinate frame origin using the mass barycenter $\mathbf{b}(M)$, computed as an area-weighted average of triangle centroids as defined in \ref{step2.5}, \nameref{step2.5}:

\begin{equation}
\mathbf{b}(M) = \frac{\sum_{t \in T} A_t \cdot \mathbf{c}_t}{\sum_{t \in T} A_t}
\end{equation}

where $T$ denotes the set of triangular faces, $A_t$ is the area of triangle $t$, and $\mathbf{c}_t$ is its centroid. For degenerate cases where $\sum_{t \in T} A_t < \epsilon_{\text{area}}$ (we use $\epsilon_{\text{area}} = 10^{-12}$), we fall back to the simple vertex mean. The translation transformation is:

\begin{equation}
v_i^{(1)} = v_i - \mathbf{b}(M)
\end{equation}

To ensure numerical precision, we apply a two-pass recentering approach. After the initial translation, we recompute the residual barycenter $\mathbf{b}_{\text{res}} = \mathbf{b}(V^{(1)})$. If $\|\mathbf{b}_{\text{res}}\| > \epsilon_{\text{recenter}}$ (with $\epsilon_{\text{recenter}} = 10^{-9}$), we apply a correction:

\begin{equation}
v_i^{(1)} \leftarrow v_i^{(1)} - \mathbf{b}_{\text{res}}
\end{equation}

This two-pass approach addresses numerical drift and degeneracy effects that can occur with large meshes or poorly conditioned geometry, ensuring that the mesh is precisely centered even in challenging cases.

\textbf{Step 3: Alignment (Pose Normalization).} We align the shape's principal axes with the coordinate frame using Principal Component Analysis (PCA) \cite{mackiewicz1993principal} on the centered vertices. The covariance matrix of the vertex positions is computed and decomposed to obtain three orthogonal eigenvectors. Let $\mathbf{e}_1, \mathbf{e}_2$ denote the eigenvectors corresponding to the two largest eigenvalues (major and medium axes). The third eigenvector (minor axis) is computed as $\mathbf{e}_3 = \mathbf{e}_1 \times \mathbf{e}_2$ to ensure a right-handed orthonormal basis. All eigenvectors are normalized to unit length.

The alignment transformation projects each vertex onto the new coordinate system defined by these principal axes:

\begin{equation}
v_i^{(2)} = \begin{bmatrix}
v_i^{(1)} \cdot \mathbf{e}_1 \\
v_i^{(1)} \cdot \mathbf{e}_2 \\
v_i^{(1)} \cdot \mathbf{e}_3
\end{bmatrix}
\end{equation}

This transformation ensures that the shape's principal axes align with the $x$, $y$, and $z$ coordinate axes respectively, providing a canonical orientation that eliminates rotation variations between shapes.

\textbf{Step 4: Flipping (Orientation Consistency).} Although PCA alignment establishes a canonical pose, it leaves an ambiguity in the sign of each principal axis (each eigenvector can be multiplied by $-1$ without affecting the eigenvalue decomposition). To resolve this ambiguity and establish consistent orientation across all shapes, we apply a moment-based test.

For each coordinate axis $i \in \{0, 1, 2\}$, we compute a signed moment:

\begin{equation}
f_i = \sum_{t \in T} \text{sign}(C_{t,i}) \cdot C_{t,i}^2
\end{equation}

where $C_{t,i}$ is the $i$-th coordinate of triangle $t$'s centroid. This quantity measures the distribution of mass along each axis, with positive values indicating that more mass lies on the positive side and negative values indicating the opposite. We then apply axis-wise flipping to ensure positive moments:

\begin{equation}
v_i^{(3)} = v_i^{(2)} \odot \begin{bmatrix}
\text{sign}(f_0) \\
\text{sign}(f_1) \\
\text{sign}(f_2)
\end{bmatrix}
\end{equation}

where $\odot$ denotes element-wise multiplication. If $f_i = 0$ (indicating perfect symmetry), we set $\text{sign}(f_i) = 1$ to avoid unnecessary flipping. This moment test ensures that similar shapes are oriented consistently, which is essential for rotation-invariant feature extraction.

\textbf{Step 5: Scaling.} The final step scales the shape to fit within a unit bounding box while maintaining aspect ratios. We compute the extent of the aligned and flipped mesh along each axis:

\begin{equation}
d_i = \max_j v_{j,i}^{(3)} - \min_j v_{j,i}^{(3)}, \quad i \in \{0,1,2\}
\end{equation}

and identify the maximum extent:

\begin{equation}
d_{\max} = \max(d_0, d_1, d_2)
\end{equation}

Each vertex is then uniformly scaled by the reciprocal of this maximum extent:

\begin{equation}
v_i^{(4)} = \frac{v_i^{(3)}}{d_{\max}}
\end{equation}

This uniform scaling ensures that the longest dimension of the bounding box equals 1.0 while preserving the shape's aspect ratios. All normalized shapes thus fit within a unit cube centered at the origin.

Following the scaling step, we apply a final safety check by recomputing the barycenter $\mathbf{b}_{\text{final}} = \mathbf{b}(V^{(4)})$. If $\|\mathbf{b}_{\text{final}}\| > \epsilon_{\text{recenter}}$, we apply a final centering correction:

\begin{equation}
v_i^{(4)} \leftarrow v_i^{(4)} - \mathbf{b}_{\text{final}}
\end{equation}

This post-scaling recenter pass ensures that the normalized mesh remains precisely centered at the origin, which is critical for rotation-invariant feature extraction and fair similarity comparisons.

\subsubsection{Implementation and Validation}

Our implementation processes the entire dataset through a unified preprocessing pipeline that integrates all five normalization steps. The pipeline includes several design features to ensure robustness and facilitate debugging:

\begin{itemize}
    \item \textbf{Smart skip logic}: Already-processed shapes are detected and skipped to enable efficient re-runs and iterative refinement of the pipeline
    \item \textbf{Step-by-step output}: For validation purposes, we save intermediate OBJ files after each normalization step:
    \begin{itemize}
        \item \texttt{00\_original.obj}: Original mesh from the dataset
        \item \texttt{01\_remeshed.obj}: After adaptive remeshing (only present if remeshing was applied)
        \item \texttt{02\_translated.obj}: After barycenter translation
        \item \texttt{03\_aligned.obj}: After PCA alignment
        \item \texttt{04\_flipped.obj}: After moment-based flipping
        \item \texttt{05\_scaled.obj}: Final normalized mesh
    \end{itemize}
    \item \textbf{Comprehensive validation}: Each processed shape undergoes extensive validation checks:
    \begin{itemize}
        \item Centering error analysis (distance from barycenter to origin)
        \item PCA eigenvalue ordering verification (ensuring $\lambda_1 \geq \lambda_2 \geq \lambda_3$)
        \item Moment test validation (confirming positive signed moments)
        \item Bounding box verification (confirming maximum extent equals 1.0)
        \item Cross-step consistency checks (ensuring each transformation preserves mesh topology)
    \end{itemize}
    \item \textbf{Enhanced numerical robustness}: The implementation uses area-weighted barycenter computation with fallback mechanisms for degenerate cases, two-pass recentering to handle numerical drift, and double-precision floating-point arithmetic throughout
\end{itemize}

The preprocessing pipeline successfully processed all 2,483 shapes in the dataset with 100\% success rate. Validation metrics confirm that our implementation achieves high mathematical precision:

\begin{itemize}
    \item Mean centering error: $9.49 \times 10^{-15}$ (effectively zero within floating-point precision)
    \item Maximum centering error: $7.53 \times 10^{-13}$ (well within numerical tolerance)
    \item Mean scaling error: $3.30 \times 10^{-17}$ (negligible)
    \item Maximum scaling error: $2.22 \times 10^{-16}$ (within machine epsilon)
    \item 100\% compliance with eigenvalue ordering ($\lambda_1 \geq \lambda_2 \geq \lambda_3$)
    \item 100\% correct moment sign after flipping (all axes show positive moments)
\end{itemize}

These results demonstrate that our implementation achieves the mathematical precision required for robust feature extraction. The normalized shapes are stored in the \texttt{UnifiedPreprocessed} directory, organized by category, with accompanying metadata files containing processing statistics and validation results for each shape.

Figure \ref{fig:normalization_steps} illustrates the normalization pipeline applied to a representative shape, showing the geometric transformation at each step. The step-by-step validation files enable visual inspection of the normalization process and facilitate debugging when extending the pipeline to new datasets.

\subsubsection{Integration with Viewer Application}

The normalized shapes are seamlessly integrated into our interactive viewer application through a dedicated caching system, which provides efficient access to pre-computed normalized vertices without redundant computation. Users can toggle between original and normalized views using the "Normalized" checkbox in the shape information panel, as shown in Figure \ref{fig:viewer_normalization}. This integration enables direct visual validation of the normalization pipeline and supports comparative analysis of shape features before and after normalization.

The processing step slider in the viewer allows users to inspect intermediate normalization steps interactively, with intelligent fallback logic to handle missing files. Since shapes already within the acceptable vertex range skip the remeshing step, they do not have a \texttt{01\_remeshed.obj} file. In such cases, the slider automatically displays the \texttt{00\_original.obj} file when attempting to view the remeshing step, ensuring continuous visual inspection of the pipeline regardless of which processing steps were actually applied. This adaptive behavior provides transparency into the preprocessing pipeline and helps users understand which transformations were necessary for each specific shape, supporting both quality control and educational purposes.
